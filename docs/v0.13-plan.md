# Arena-Agents v0.13.0 开发方案与测试方案

> 状态：**已冻结 rev1**（用户已确认整份方案，含 F25；尚未开工，等用户通知开始）。基线：`main` 58875fd（v0.12.1）。
> 冻结后决策按 F# 追加编号，修改须追加新条目并升 rev（与 v0.12.1 方案的 E# 规则相同）。
> v0.12 的 D#、v0.12.1 的 E# 继续有效，除非被本文的 F# 明确替换。
> 前置方案：[v0.12.1-plan.md](v0.12.1-plan.md)；现行契约：[v0.12-contracts.md](v0.12-contracts.md)。

## 0. 目标

v0.13 做四件事：

1. **接管**：玩家可以在对局未开始或暂停时接管某个玩家座位，以这个座位的身份发言、投票、使用技能；退出接管后交还给 agent。
2. **人类输入**：接管后每个频道有自己的输入框（像多人聊天软件），请求卡片可点击，禁言时能打字但不能发送。
3. **存储重做**：数据放在程序目录下的 `data/`；设置里只有“导出存档 / 导入存档”，存档是单个 `.arenaagents` 文件，API key 可用密码加密导出；提供 v0.12.1 → 存档的转换脚本。
4. **历史对局**：列表、删除、继续、带暂停和倍速的重放。

## 1. 决策记录（F1–F36）

### 1.1 接管

| # | 决策 |
|---|---|
| F1 | **视角栏改为 `[视角▾] [切换] [接管]`。** 选下拉框不再立即切换，点“切换”才生效（只换视角，不接管）。选中“上帝视角”时“接管”不可用。 |
| F2 | **接管条件。** 只能接管玩家座位（主持人不能接管），同一时间只接管一个座位；只在对局**未开始**或**已暂停**时可用，运行中、已结束时按钮不可用；点击后弹确认窗口。服务端同样校验，不满足返回 409。 |
| F3 | **接管期间。** 视角锁定为被接管座位（**只在前端锁定**；服务端仍下发上帝视角数据，按 F12 能看到——用户选择的方案 B，列为已知限制）。视角栏换成“🎮 正在扮演 3 · Carol `[退出接管]`”；玩家详情里的“以 X 视角观看”禁用；手机上这一栏留在首行，不收进 ⋯ 菜单。 |
| F4 | **退出接管。** 只在对局不在运行时可用（未开始 / 已暂停 / 已结束）；运行中按钮不可用，提示先暂停；点击后弹确认窗口。退出后重建这个座位 agent 的会话：下次激活拿到完整的首条消息（状态板 + 笔记 + 全部可见历史），人类以它名义说过的话作为它自己的历史出现。 |
| F5 | **重新发牌。** 未开始时接管，接管后的界面提醒“你已经知道身份，建议重新发牌”，并带一个「重新发牌」按钮（复用 `POST /api/control/shuffle-identities`，重发全部座位的身份，不换对局、不改名册）。**开始对局后严格禁止**：按钮隐藏；服务端在状态不是 `idle`、或账本里已有对局开始记录时一律拒绝（409）；重新发牌与“开始”在同一把控制锁里串行执行，杜绝连点 / 并发造成开局后重发。 |
| F6 | **不告诉任何 agent。** 主持人和其他玩家都不知道有人类参与；退出接管后也不告诉被接管的 agent。观战界面在该座位卡片上显示“🎮 人类操作中”。 |
| F7 | **时限不变。** 发言权时长、请求截止时间仍由主持人决定；界面显示倒计时，超时按引擎现有规则处理（默认答案 / 发言权结束）。 |
| F8 | **复盘照常。** 有人类代打过的座位，赛后复盘和战绩与其他座位相同（由该座位的模型复盘）。 |
| F9 | **被接管的座位仍须绑定模型**（退出接管后和赛后复盘都要用）；开始 / 继续的绑定检查不豁免它。接管期间该座位不创建 agent、不产生 token。 |
| F10 | **接管状态随对局保存。** 服务重启后恢复为“已暂停 + 仍在接管”；接管是服务端状态，所有打开的浏览器标签页同步进入接管模式。 |
| F11 | **人类动作走世界的同一个提交闸门。** 新接口 `POST /api/seat/speak|pass|respond|ability`，服务端以“当前被接管的座位”作为动作者（客户端不能替其他座位操作）；轮次、字数、条数、截止时间等规则与 agent 完全相同。对局暂停时动作被拒绝。发言草稿过期（`STALE`，期间发生了身份 / 阶段变化）时保留草稿并提示确认后重发。 |
| F12 | **座位状态由服务端计算并推送。** 被接管座位在每个频道能否发言、原因、当前字数上限、我的发言权剩余条数和秒数、待答请求、可用技能，由服务端按引擎的发言规则（`speech_gate` / 状态板）算出，放进会话快照并在每次世界变化后推送 `takeover.updated`；前端不自己推算。 |

### 1.4 存档

| # | 决策 |
|---|---|
| F26 | **“设置”里只有“导出存档 / 导入存档”。** 顶栏的“工作文件夹”按钮改为“⚙ 设置”。同时删除：顶栏“保存”（对局每次变化 0.5 秒内自动保存）、“导入存档”（单局 JSON）、“会话”窗口；名册菜单的“导出全部记忆（.zip）”“导入记忆包”。系统里不存在其他任何导出。保留：Provider、模型绑定、预算上限、“清除全部记忆”、“本局加载记忆”、玩家详情里编辑性格 / 记忆。 |
| F27 | **`.arenaagents` 格式**：zip 容器，内容不加密（API key 除外）。根目录 `manifest.json` 记录格式名 `arenaagents`、格式版本、应用版本、创建时间、存档 id、每个文件的路径 / 大小 / SHA-256、内容统计（对局数、Provider 数……）、是否含 key、是否含日志，以及对整份文件清单的 SHA-256。见 §2.2。 |
| F28 | **导出流程**：① 是否导出 API key；② 选“是”则输入两次密码（≥ 12 位，大写 / 小写 / 数字 / 符号至少三类，前后端都校验）；③ 是否包含思考日志（默认包含）；④ 后台打包并显示进度；⑤ 完成后弹窗显示保存路径（`data/exports/arena-<时间>.arenaagents`）并提供下载按钮。对局运行中也能导出（先刷新自动保存，导出那一刻的快照）。 |
| F29 | **API key 加密**：`scrypt(密码, 16 字节随机盐, n=2^17, r=8, p=1)` 派生 32 字节密钥 → AES-256-GCM（12 字节随机 nonce，AAD 绑定存档 id 和格式版本）。盐、参数、nonce 明文存放；密码不写入存档、不写日志、不回传。密码错误或内容被改动时 GCM 校验失败，不导入任何 key。 |
| F30 | **导入流程**：① 上传（显示进度，上限 2 GB，`ARENA_MAX_ARCHIVE_BYTES` 可改；先写临时文件）；② 校验：格式名、格式版本（不支持更新的格式，提示升级）、清单完整（不多不少）、每个文件的 SHA-256、路径合法（无绝对路径 / `..`）、解压总量和条目数上限、每局对局通过 v5 结构校验；③ 显示摘要；④ 含 key 时输入密码，或选择“跳过 API key”；⑤ 整体替换，显示进度；⑥ 完成后刷新页面，导入的当前对局以“已暂停”恢复。只能在对局不在运行时导入。 |
| F31 | **导入前备份与回滚**：替换前把当前数据移到 `data/backups/<时间>/`（其中的 key 仍是本机加密，只能在本机用），导入失败自动回滚；保留最近 3 份；没有界面，手动恢复步骤写进 README。 |
| F32 | **跳过 key 时**：本机已有同一 Provider（id 相同，通常是导入自己导出的存档）的 key 则保留本机的 key；否则该 Provider 显示“未设置 API Key”，开始对局时提示。 |
| F33 | **转换脚本** `tools/migrate_v0121_to_archive.py`：读取 v0.12.1 工作区（默认 `%USERPROFILE%\Arena-Agents\Default`，可用 `--workspace` 指定），解密 Provider 和对局，对局 v4 → v5，带上设置、名册、价格表、日志，生成 `.arenaagents`；询问是否导出 key 及密码（规则同 F28）。必须用同一 Windows 用户运行，或提供主密钥。v0.12.0 及更早的存档跳过并列在报告里。只读源目录，不修改任何旧文件。 |

## 2. 数据格式

### 2.1 数据目录

```text
<程序目录>/data/
├─ .lock                 进程锁
├─ settings.json         默认绑定、模板、上次对局、预算默认值、界面偏好（含旧数据提示是否已忽略）
├─ providers.json        Provider 注册表（不含 api_key）
├─ secrets.v1.enc        {provider_id: api_key}，本机加密（AES-256-GCM）
├─ master.v1.dpapi       Windows：DPAPI 包装的本机密钥
├─ pricing.json          价格表（公开数据）
├─ roster/               roster.json、N*.persona.md、N*.memory.md（与 v0.12.1 相同）
├─ games/
│  ├─ index.json         历史列表索引（可重建）
│  └─ <id>/game.json     对局（格式 v5，明文）+ game.prev.json（上一份完好的副本）
├─ logs/<id>/trace-*.jsonl
├─ exports/              导出的 .arenaagents
├─ backups/<时间>/       导入前的备份（保留 3 份）
└─ tmp/                  上传中的文件
```

### 2.2 `.arenaagents`

```text
arena-20261118-0042.arenaagents   （zip）
├─ manifest.json
├─ settings.json
├─ providers.json                 不含 api_key
├─ pricing.json
├─ roster/…
├─ games/index.json, games/<id>/game.json
├─ logs/<id>/trace-*.jsonl        可选（F28 ③）
└─ secrets.enc                    可选（F28 ①）：{kdf, n, r, p, salt, nonce, aad, ciphertext}
```

`manifest.json` 示例：

```json
{
  "format": "arenaagents",
  "format_version": 1,
  "app_version": "v0.13.0",
  "archive_id": "4f1c…",
  "created_at": "2026-11-18T00:42:00-08:00",
  "contents": {"games": 12, "providers": 2, "roster_seats": 12, "has_secrets": true, "has_logs": true},
  "files": [{"path": "games/ab12/game.json", "size": 81234, "sha256": "…"}],
  "files_sha256": "…"
}
```

校验的能力边界：SHA-256 能发现损坏和截断，但防不住有人故意改内容后重算校验值（没有密钥无法签名）；`secrets.enc` 由 GCM 认证，被改动或密码错误都解不开。

### 2.3 对局 v5 新增字段

```json
{
  "schema_version": 5,
  "takeover": {"seat": "N3"},
  "human_spans": [{"seat": "N3", "from_seq": 0, "to_seq": 418}],
  "created_at": "…", "started_at": "…", "finished_at": null
}
```

`takeover.seat` 为 `null` 表示未接管；`human_spans` 的 `to_seq` 为 `null` 表示仍在接管。

## 3. 接口变化

新增（写接口沿用现有访问规则：设置了 `ARENA_API_TOKEN` 时需要令牌，否则只允许本机）：

| 接口 | 说明 |
|---|---|
| `POST /api/takeover` `{seat}` | 接管（F2） |
| `POST /api/takeover/release` | 退出接管（F4） |
| `POST /api/seat/speak` `{channel_id, content, based_on_seq}` | 人类发言（F11） |
| `POST /api/seat/pass` `{channel_id}` | 结束发言（F15） |
| `POST /api/seat/respond` `{request_id, value, reason?}` | 回答请求（F17） |
| `POST /api/seat/ability` `{ability_id, params}` | 使用技能（F16） |
| `GET /api/games`、`DELETE /api/games/{id}`、`POST /api/games/{id}/load` | 历史列表、删除、继续（F34、F35） |
| `GET /api/games/{id}/replay` | `{initial, events[{seq, gt, type, data}], duration_gt}`（F36） |
| `POST /api/archive/export` `{include_keys, password?, include_logs}` → `{job_id}` | 导出（F28） |
| `GET /api/archive/jobs/{job_id}`、`GET /api/archive/exports/{name}` | 进度查询、下载 |
| `POST /api/archive/import`（请求体为文件流）→ `{import_id, summary}` | 上传并校验（F30 ①②③） |

| `POST /api/notices/legacy-data:dismiss` | 忽略旧数据提示（F24） |

`POST /api/control/shuffle-identities`：不在 `idle`、或账本已有开始记录时返回 409（F5）。

删除：`/api/workspaces*`、`/api/session/save`、`/api/session/import`、`/api/sessions`、`/api/sessions/{id}`、`/api/sessions/{id}/load`、`/api/roster/memory:export`、`/api/roster/memory:import`。

## 6. 测试方案

### 6.1 离线测试（pytest，全部不联网）

**存储与存档：**
- 数据目录：默认是程序目录下的 `data/`，与当前目录无关；`ARENA_DATA_DIR` 覆盖生效；进程锁冲突时拒绝启动。
- 只有 key 加密：`data/` 里所有文件都搜不到 key 明文，对局文件是可读的 JSON；`secrets.v1.enc` 改动 / 换密钥 / 截断都报错。
- 对局 v5：保存、恢复、上一份副本回退；索引损坏后自动重建。
- 导出 → 导入往返：设置、Provider、名册、对局、日志逐字节一致；带 key 往返后 key 一致。
- 密码：错误密码、篡改 `secrets.enc`、篡改盐 → 不导入任何 key；密码不出现在存档、日志、响应里；弱密码被拒绝（前后端规则一致）。
- 校验：改一个文件 / 删一个文件 / 多一个文件 / 路径穿越 / 绝对路径 / 超大解压量 / 格式版本更新 → 全部拒绝且当前数据不变。
- 备份与回滚：导入中途失败自动回滚；备份只保留 3 份；跳过 key 时同 id Provider 保留本机 key。
- 转换脚本：用测试夹具构造 v0.12.1 工作区（加密 Provider、v4 对局、旧版对局、名册、日志），转换后导入成功；旧版对局被跳过并报告；源目录未被修改。
- 旧数据提示：条件满足时出现，忽略后不再出现。

**接管：**
- 只能在未开始 / 已暂停时接管，只能接管玩家座位；运行中退出接管被拒绝，未开始 / 已暂停 / 已结束可以退出。
- 接管座位没有 agent、不产生调用；投递给它的消息不会激活任何模型。
- 座位接口：以被接管座位为动作者；暂停时被拒绝；轮次 / 字数 / 条数 / 截止时间规则与 agent 一致；`STALE` 正确返回。
- `takeover.updated`：发言权变化、频道关闭 / 冻结、请求开关、技能启用 / 停用后推送的状态正确，字数上限与 `speech_gate` 一致（自由讨论、私聊、发言权三种）。
- 重新发牌：未开始时可用；开始后、暂停后、结束后都返回 409；“开始”和“重新发牌”并发时不会出现开局后重发。
- 退出接管后该 agent 的下一次激活是完整首条消息，历史里包含人类的发言。
- 服务重启后恢复为“已暂停 + 仍在接管”。
- 演示机器人对局：接管一个座位，人类动作脚本化，整局能打到终局。

**历史与重放：**
- 列表摘要正确（状态、胜方、时长、费用、人类参与）；删除对局不改动名册文件；当前对局不能删除。
- 重放投影：演示对局整局的事件逐条应用后，最终的信息流、请求卡片、身份标签、频道状态与该局快照一致（与现有 `replay_check` 同样的思路）。
- 按视角重放时只出现该视角可见的内容。

### 6.2 前端测试（node）

- 视角栏：选下拉框不切换，点“切换”才切换；接管 / 退出的按钮可用性与确认窗口；接管期间视角锁定、详情面板按钮禁用。
- 输入框：按频道切换、草稿保留、字数计数、发送按钮的五种状态、结束发言和技能按钮的出现条件、Enter / Shift+Enter。

- 重新发牌按钮：只在未开始时出现。
- 设置：导出流程（是否导出 key、密码强度、两次输入不一致）、进度、结果弹窗；导入流程（上传进度、摘要、密码 / 跳过、进度）。

### 6.3 浏览器验证（opencli，真实浏览器，演示实例 + 模拟服务）

## 7. 风险与已知限制

| 风险 | 应对 |
|---|---|
| 接管只在前端锁定视角，按 F12 能看到上帝视角数据（F3） | 用户已接受；列入已知限制；以后需要时可改为服务端按座位下发 |
| 人类反应慢，发言权 / 请求超时 | 倒计时与“待你操作”标记；超时按引擎现有规则处理（F7） |
| 数据在程序目录下：删除或重装程序目录、`git clean -xdf` 会删掉数据 | README 明确警告；建议定期导出存档 |
| 本机加密的 key 不能随 `data/` 复制到别的机器 / 用户 | 用带密码的存档迁移（F28） |
| 忘记存档密码 | key 无法恢复（设计如此）；可跳过 key 导入其余内容（F30） |
| 重放精度：账本里没有的界面细节（如逐秒倒计时）只能近似 | 用“最终状态一致”的测试兜底（§6.1） |
| 存档较大（含日志） | 流式打包与上传、进度显示、2 GB 上限可调；导出时可不含日志 |
| Docker 换卷后看不到旧数据 | 文档给出用转换脚本处理旧卷的步骤 |

## 8. 已确认

| 问题 | 结论 |
|---|---|
| 接管后的信息隔离 | 只在前端锁定（F3） |
| 退出接管的时机 | 不运行时（未开始 / 已暂停 / 已结束）都可以（F4） |

| 输入框 | 与频道绑定，每个频道一个（F13） |
| 技能 / 猎人开枪 / 质询 | 技能按钮放主动技能；猎人开枪保持为请求卡片；质询走私聊（F16、F19） |

| v0.9 时代的自动迁移 | 删除（F25） |
