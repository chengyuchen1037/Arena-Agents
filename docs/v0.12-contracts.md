> 依据 [v0.12-async-agents-plan.md](v0.12-async-agents-plan.md)（rev 5，已冻结，决策 D1–D25）。本文把方案落成**可并行实现的精确语义**。

## 0. 约定

- Python 3.12，虚拟环境 `.venv`；运行时务必设 `PYTHONUTF8=1`。**没有 pytest-asyncio**：异步测试用 `asyncio.run(...)` 包一层。
- **时间**：世界里的所有期限都是**游戏秒**（`clock.now()`，暂停时不走，D18）。运行时的防抖、看门狗用事件循环的真实时间。
- **引擎中立**：`app/world`、`app/runtime`、`app/agents`、`app/orchestrator` 里的 Python 源码不得出现任何具体游戏词汇（`tests/v12/test_neutrality.py` 会扫描）。例外：`app/demo/`。
- 世界是**单线程同步**的：处理函数里不能 `await`，也不能做阻塞 I/O。
- 所有用户可见的文字用**中文**；日志与代码注释中英文均可。
- 所有 JSON 载荷里的 id 都是字符串；`moderator` 是主持人的固定 id，`engine` 是引擎。

## 2. 世界（`app/world`）

### 2.1 `World` 的装配（world-chat）

```python
class World(WorldCore):                       # app/world/world.py
    chat: ChatModule                          # app/world/chat.py
    game: GameModule                          # app/world/game.py
    @classmethod
    def new_game(cls, spec, players: list[dict], clock, *, seed: int | None = None) -> "World"
        # players: [{"id","seat","name","persona"}]；创建玩家、系统私聊、发牌；状态 idle，未运行
    @classmethod
    def load(cls, data: dict, spec, clock) -> "World"        # 还原 dump() 的结果（clock 已 set 到 data["clock_now"]）
    # WorldPort 要求的其余方法：board / memory / write_note / read_notes_text / compact / display_name ...
```

`GameModule` 调用 `self.w.chat.freeze_channel(channel_id, reason)`（world-chat 提供，见 §2.4）。

### 2.2 提交闸门（`WorldCore._submit`，已实现）

顺序：未知类型 → `INVALID_PARAMS`；未运行 → `GAME_NOT_RUNNING`；未知参与者 → `UNKNOWN_PLAYER`；
主持人/玩家操作错配 → `FORBIDDEN`；载荷校验 → `INVALID_PARAMS`；`speak`/`speak_template` 的过时检查（自 `based_on_seq` 之后出现过 `spec.invalidates_drafts` 里的账本条目）→ `STALE`；
剧本约束 → `CONSTRAINT`；最后分发给处理函数。处理函数返回 `Receipt`。**处理函数里的拒绝优先于副作用：被拒绝时不得改动任何状态。**

### 2.3 各 Intent 的语义

**发言类（world-chat）**

| Intent | 语义 |
|---|---|
| `speak` | ① 频道不存在 `UNKNOWN_CHANNEL`；② 不是成员 `NOT_MEMBER`；③ 模式：`closed`/`listen` → `CHANNEL_CLOSED`（系统私聊被关闭时消息说明“你与主持人的私聊已被关闭”）；`frozen` → `NO_FLOOR`；`turn`/`queue` → 须持有**活跃且未暂停**的令牌，否则 `NO_FLOOR`（`data` 带 `holders` / `current`）；`free` → 成员不在 `readonly`、也在 `writers`（若设置）内，否则 `NO_FLOOR`；每人条数达上限 → `QUOTA_EXCEEDED`。④ **截断（D19）**：单条上限 = `min(令牌/自由讨论的单条上限, 令牌剩余总字数)`；超出部分截掉，回执 `truncated={"dropped_chars","kept_chars"}`；可写字数为 0 → `NO_FLOOR`。系统私聊：单条上限 `defaults.dm.max_chars_per_message`，不限条数，不需要令牌。⑤ 写入 `message`（`kind: speech`）；令牌用掉 1 条、记字数；令牌条数或总字数用尽 → 令牌以 `used` 结束。回执带 `floor_left`。 |
| `speak_template` | 与 `speak` 同样检查模板：不存在 `UNKNOWN_TEMPLATE`；`users` 不含玩家 `FORBIDDEN`；参数用 `render.validate_params`。**模板文本不截断、不受字数上限约束**，但仍消耗 1 条发言额度并计入字数。`message.kind = template`，带 `template_id` / `params`。 |
| `pass` | 持有活跃令牌 → 令牌以 `pass` 结束；`free` 频道 → 空操作的成功回执；否则 `NO_FLOOR`。 |

**主持人的频道与发言权（world-chat）**

| Intent | 语义 |
|---|---|
| `mod.announce` | 模板须存在，且 `users ∈ {moderator, any}`；渲染；`message.kind = announce`。主持人可在任何自己是成员的频道写（含 `closed`、`listen`、被冻结的频道）。 |
| `mod.send_message` | 自由文本，按 `defaults.moderator.max_chars_per_message` 截断；`kind = speech`。 |
| `mod.create_channel` | `channel_id` 已存在 → `ALREADY_EXISTS`；成员须是玩家 id（否则 `UNKNOWN_PLAYER`）；主持人自动加入；`mode=free` 时用 `defaults.free` 初始化 `FreeState`。写 `channel.created`。 |
| `mod.update_channel` | 改名、增减成员（**不能移除主持人；系统私聊不能增减成员**，但可以改 `mode`）、`readonly_members`、`mode`（`closed`/`free`/`listen`）、`free_limits`。离开 `turn`/`queue`/`free` 时撤销令牌（`floor.revoked`）；清除 `frozen`；进入 `free` 时用默认值初始化（`free_limits` 覆盖）；`free_limits` 同时**重置自由讨论的所有 advisory 标记**。写 `channel.updated`。 |
| `mod.open_floor` | `mode=turn`：`holders` 须全是频道成员；每人一个活跃令牌（限额 = `limits` 覆盖 `defaults.floor`；`deadline = now + duration_s`）；替换原有的发言组（旧令牌撤销，`reason: replaced`）；频道 `mode = turn`，清除 `frozen`。`mode=free`：进入自由讨论（`holders` 非空表示只有这些人可写）。 |
| `mod.set_floor_queue` | 按 `order` 建队列（成员校验同上）：第一个令牌 `active`，其余 `pending`；一次只有一个活跃令牌。令牌结束后自动激活下一个并投递 `floor.granted`。 |
| `mod.pause_queue` / `mod.resume_queue` | 暂停：`group.paused = True`，活跃令牌的剩余时间存入 `remaining`、`deadline = None`；持有人收到 `floor.paused`（打断）。恢复：`deadline = now + remaining`，持有人收到 `floor.granted`；同时清除 `frozen`。 |
| `mod.close_floor` | 撤销所有令牌（`reason: closed`），或结束自由讨论；频道 `mode = closed`，清除 `frozen`；持有人收到 `floor.revoked`（打断）。写 `floor.closed`。 |

**令牌的结束（`_end_token(group, token, reason)`）**：状态变 `done`；写 `floor.token_ended`（频道成员可见）；`queue` → 激活下一个并写 `floor.granted`；
当组内全部结束：组 `completed`，频道变为 `closed`、`group = None`，写 `floor.completed`，并 **URGENT 唤醒主持人**（`floor.completed`，载荷含每人的结果）。
超时在 `tick()` 中处理（`reason: timeout`，给持有人发 `floor.revoked`，`interrupt=True`、ambient）。

**自由讨论的 advisory（D20）**：`tick()` 里满足以下之一时，各触发一次，URGENT 唤醒主持人（`free.advisory`，载荷 `reason: time | chars | silence`，附统计）：
`now - started_gt ≥ duration_s`；`chars_used ≥ max_chars_total`；`now - last_message_gt ≥ silence_s`（没人说过话则从 `started_gt` 起算）。**这些都不会自动关闭频道。**新消息会重置 `silence` 标记。
**每人条数上限是硬限制**（`QUOTA_EXCEEDED`）；`max_chars_per_message` 是硬限制（截断）；总字数与时长只是 advisory。

**游戏类（world-game）**

| Intent | 语义 |
|---|---|
| `respond` | 请求须存在、`status=open`、操作者在 `to` 中，否则 `UNKNOWN_REQUEST` / `REQUEST_CLOSED` / `FORBIDDEN`。`choice`：`value` 必须是选项 id，否则 `INVALID_TARGET`（消息里列出合法 id）；`text`：按 `defaults.request.max_text_chars` 截断。**关闭前可以重复作答，以最后一次为准**（`data.replaced=true`）。写 `request.answered`；全员作答后立即关闭请求。 |
| `mod.open_request` | 目标须是玩家（`UNKNOWN_PLAYER`）；创建 `RequestState`（期限 `duration_s` 或 `defaults.request.duration_s`）。写 `request.opened`；每个目标收到 URGENT 的 `request.opened`；回执 `data.request_id`。 |
| 请求关闭 | 全员作答，或到达期限（`tick`）：未作答者若有 `default` 则记为 `defaulted`；写 `request.closed`（仅主持人可见，含按座位顺序排列的全部答案、`defaulted`、`missing`）；URGENT 唤醒主持人（`request.closed`）；未作答的目标收到 `request.cancelled`（`reason: expired`，打断、ambient）。**密封**：`request.answered` 的 `visible_to_ids = []`，直到关闭才随 `request.closed` 公开给主持人。 |
| `mod.cancel_request` / `mod.reopen_request` | 取消：`status=cancelled`，目标收到 `request.cancelled`（打断）。重开：只能克隆已关闭或已取消的请求（新 id，`reopens` 指向旧 id；`to` 默认沿用原目标）。 |
| `use_ability` | 能力须存在（`UNKNOWN_ABILITY`）、已启用且在 `allowed` 内（`ABILITY_DISABLED`）、操作者在 `holders` 表达式的结果里（`FORBIDDEN`）、次数未用完（`QUOTA_EXCEEDED`）；参数用 `validate_params`。成功后：写 `ability.used`（操作者与主持人可见）→ 若有 `reveal`，以操作者名义在 `reveal.channel_id` 里发一条 `kind=ability` 的消息（**不受发言权限制**）→ 对 `freeze_channels` 里的每个频道调用 `chat.freeze_channel`（D25）→ URGENT 唤醒主持人（`ability.used`）。 |
| `mod.enable_ability` / `mod.disable_ability` | 切换 `AbilityState.enabled`；`enable` 可限定 `holders`。写 `ability.enabled/disabled`（仅主持人可见）。能力默认关闭。 |
| `challenge` | 须有系统私聊且未关闭（否则 `CHANNEL_CLOSED`）；内容按 `defaults.dm.max_chars_per_message` 截断；创建 `TicketState`（`t1`、`t2`…）；在 `dm-{玩家}` 里 `post_message(kind="challenge", extra={"ticket_id"})`（主持人收到 URGENT）；发 UI 事件 `challenge.opened`。不需要额外的账本条目。**不限次数（D22）。** |
| `mod.resolve_challenge` | 工单须存在且为 `open`；在该玩家的私聊里 `post_message(kind="reply", extra={"ticket_id","verdict"})`（玩家收到 URGENT）；工单变 `resolved`；发 UI 事件 `challenge.resolved`。 |
| `mod.update_player` | 增删 tag、合并 `attributes`。写 `player.updated`（本人与主持人可见，全量数据）；若变动涉及 `spec.setup.public_tags`，再写 `player.public_changed`（其余所有人可见，只含公开 tag 的增减）。发 UI 事件 `player.updated`（`tags` 与 `out`）。**不会自动改变频道成员或发言权。** |
| `mod.set_phase` / `mod.update_dashboard` | 写 `phase.changed` / `dashboard.updated`（所有人可见），发对应 UI 事件。 |
| `mod.random` | 用 `world.rng`（可复现）；结果写 `random.drawn`（仅主持人可见），并放在回执 `data.result`。`int`：闭区间；`choice`：k 个不重复项；`shuffle`：洗牌后的列表。 |
| `mod.evaluate` | 只读：执行 `spec.checks[check_id]`，回执 `data.value`（玩家视图转成 id）；未知检查项 → `INVALID_TARGET`。可带 `args`（键为标识符、不得与内置函数名冲突、值为 JSON 基本类型/列表/字典、总长 ≤ 4000）作为表达式里的额外变量；缺少表达式用到的变量 → `INVALID_PARAMS`（`data.missing`）。 |
| `mod.get_ledger` | 只读：返回主持人**可见**的条目（`data.entries`，每条含 `seq/type/channel_id/actor_id/data`）。 |
| `mod.hold_game` | `world.set_running(False, "hold:…")`；向 `ENGINE_ID` 投递 `notice/hold_game`；发 UI 事件 `game.status`。 |
| `mod.end_game` | 置 `state.status=finished`、`winner`、`summary`；写 `game.status`（所有人可见，含胜者和总结）；关闭闸门；向 `ENGINE_ID` 投递 `notice/end_game`。之后 `set_running(True)` 可继续对局（写 `game.status`，`reason: continued`）。 |

**发牌（world-game，`GameModule.deal()`，由 `new_game` 调用）**：按 `setup.identity_pool` 展开，用 `world.rng` 洗牌（`setup.shuffle`），按玩家顺序分配；
人数与池大小不一致 → 抛 `ValueError`。玩家得到 `role`、`faction`、`tags`、`attributes`；每人写一条 `player.updated`（`actor=engine`，仅本人和主持人可见，`reason: "deal"`）。
**系统私聊（D23，world-chat `create_system_dms()`）**：每人一个 `dm-{id}`，`type=dm`、`mode=free`、`system=True`、`owner`，成员为主持人和该玩家；写 `channel.created`。

### 2.4 `ChatModule.freeze_channel(channel_id, reason)`

置 `channel.frozen = True`；`queue`/`turn` 的发言组置 `paused`（剩余时间存入 `remaining`）；
所有当时**能在该频道写**的人（活跃令牌的持有人，或 `free` 的成员）收到 `floor.frozen`（`interrupt=True`、ambient）；写 `floor.frozen`（频道成员可见）。
冻结期间的 `speak` 一律 `NO_FLOOR`（“频道已被冻结，等待主持人裁决”）。主持人用 `resume_queue` / `open_floor` / `set_floor_queue` / `close_floor` / `update_channel(mode=…)` 解除。

### 2.6 投递（Envelope）目录

`priority` 决定唤醒（urgent 立即、normal 防抖后、ambient 从不唤醒空闲的 worker）；`interrupt=True` 表示“与该频道/请求有关的在途工作已经作废”，匹配的运行中 worker 会被取消。

| 收件人 | `kind` / `payload.event` | 优先级 | 打断 | 载荷 |
|---|---|---|---|---|
| 玩家 | `message` / `message.new` | 由 `core.message_priority` 决定 | – | `message_kind` |
| 玩家 | `challenge` / `challenge.resolved` | urgent | – | `ticket_id` |
| 玩家 | `floor` / `floor.granted` | urgent | – | `channel_id, mode, max_messages, max_chars_per_message, max_chars_total, seconds, position?, total?` |
| 玩家 | `floor` / `floor.revoked`、`floor.paused`、`floor.frozen` | ambient | ✔ | `channel_id, reason` |
| 玩家 | `request` / `request.opened` | urgent | – | `request_id, kind, question, options, seconds, sealed` |
| 玩家 | `request` / `request.cancelled` | ambient | ✔ | `request_id, reason(cancelled/expired)` |
| 玩家 | `notice` / `channel.created`、`channel.updated`、`player.updated`、`phase.changed` | ambient | – | 简要信息 |
| 主持人 | `floor` / `floor.completed` | urgent | – | `channel_id, group_id, mode, results[]` |
| 主持人 | `floor` / `free.advisory` | urgent | – | `channel_id, reason, ...统计` |
| 主持人 | `request` / `request.closed` | urgent | – | `request_id, reason, answers, defaulted, missing`（密封请求此时才含答案） |
| 主持人 | `challenge` / `challenge.opened` | urgent | – | `ticket_id` |
| 主持人 | `ability` / `ability.used` | urgent | – | `ability_id, actor_id, params` |
| 主持人 | `message` / `message.new` | 系统私聊中玩家发来的普通消息为 normal，其余 ambient | – | `message_kind` |
| `engine` | `notice` / `hold_game`、`end_game` | – | – | `reason` / `winner, summary` |
| 任何人 | `notice` / `game.started`、`game.resumed`、`game.continued`、`watchdog` | urgent | – | 由 orchestrator / supervisor 直接投递，不经过世界 |

### 3.2 Actor 规则

- 收件箱按 **urgent → normal → ambient** 处理。Worker 空闲时：有 urgent → 立即开始一次运行；有 normal → 在**第一条 normal 到达后 `debounce_s`**（默认 1.5s，可配置，非滑动）开始；只有 ambient → 只缓冲。
- **运行中**：到达的信封进入待处理缓冲；Worker 在**每轮 LLM 调用之后**调用 `brain.inject_message`，把缓冲里的内容注入。如果缓冲里还有 urgent / normal，那么即使这一轮没有工具调用，运行也不会结束。
- **打断**：运行中收到 `interrupt=True` 的信封，且其 `channel_id` 或 `payload.request_id` 与当前运行的 **focus** 匹配 → 取消该 worker（`task.cancel()`，等待它结束）。
  **focus** = 本次运行消费过的所有 urgent / normal 信封里出现的 `channel_id` 和 `request_id`。
  取消后，只有缓冲里仍有 urgent / normal 时才立即重启；否则回到空闲（所以 `floor.revoked` 不会白白再开一次调用）。
- **防饥饿**：同一个 agent 连续被取消 2 次后，第 3 次打断不再取消，改为注入。一次运行正常结束后计数清零。
- 每次运行 `gen_id += 1`。Worker 在提交 Intent 前再次检查自己是否仍是当前 `gen_id`。
- **对话不跨运行保留**：每次运行都用 `brain.start_message` 从世界重建上下文，所以取消不会留下不成对的 tool_call。
- **运行轮数上限**：玩家与主持人分别按 `config.max_rounds[kind][execution_depth]` 设定（`execution_depth ∈ low/medium/high/xhigh`；默认玩家 3/5/8/12，主持人 6/10/16/24）。用尽即结束。
- 运行结束的条件：模型无工具调用（且 `no_tool_nudge` 返回 `None` 或已 nudge 过一次）、`ToolOutcome.ends_run`、轮数用尽、被取消。`rebuild=True` 时，用 `brain.start_message` 重建对话并继续。
- LLM 调用失败（异常）：记录 trace，`agent.status` 回到 idle，指数退避后重新入队一次（最多 2 次），仍失败则放弃本次唤醒，并通过 `sink` 发出 `error` 事件；不得拖垮其他 agent。

### 3.3 Supervisor 规则

- `start(initial_wakes)`：启动全部 Actor 任务；对 `initial_wakes: dict[agent_id, list[Envelope]]` 投递；调用 `world.redeliver()` 后立即泵一次；启动 `world.tick()` 的轮询任务。
- 泵：`world.drain_outbox()` → 按 `target` 放进 `Agent.mailbox`（`ENGINE_ID` → 调用 `on_engine(envelope)`）；`world.drain_events()` → `sink.publish`。
- `stop()`：先停轮询和泵，再取消所有 worker 和 actor 并 `await` 结束，最后发一次 `agent.status = stopped`。**不得泄漏任务**（测试里要检查）。
- **看门狗**（真实时间，参数可注入）：`running` 时，如果所有 Agent 都空闲、`world.next_deadline() is None`、邮箱没有待处理信封、账本 `seq` 在 `watchdog_s`（默认 20s）内没有变化 → 向主持人投递 urgent `notice/watchdog`；连续 `max_watchdog_wakes`（默认 3）次唤醒都没有让 `seq` 前进 → 调用 `on_stall(reason)`（orchestrator 会 `hold_game`）。任何 seq 前进都会清零。
- 状态事件：`agent.status`（`{id, state: idle|thinking|acting|stopped}`，状态变化时发出）、`agent.metrics`（每个 agent 至多每秒一次，只有变化时）。

### 3.4 LLM 调用与记账

- 每个 Worker 的 LLM 调用：`resp = await llm.complete(agent_id, messages, tools, max_tokens=…)`；`max_tokens = spec.defaults.llm.max_tokens`。
- 成功后：`usage.record_llm(agent_id, resp)`；有 `resp.thought.strip()` → `count(..., "thinking_rounds")`；每个工具调用 `count(..., "tool_calls")`；回执 `ok=False` → `count(..., "rejections")`。
- trace 事件：`llm_call`（模型、token、耗时）、`thought`、`tool_call`（参数与结果）、`receipt`、`wake`、`cancel`、`inject`、`error`、`watchdog`。

|---|---|

- 失败的世界类工具调用会被记入 brain 里的“最近行动”（每个 agent 最近 12 条，不持久化），下次重建上下文时展示给本人。

### 4.2 上下文格式（`start_message`）

固定段落（中文小标题）：`【状态板】`（`board()` 渲染）→ `【我的记忆】`（压缩摘要 + 笔记）→ `【我最近的行动】` → `【可见历史】`（`entries_visible(after_seq=summary_upto_seq)`，按时间顺序，每行 `#seq [频道] 名字：内容`，系统类条目用一行摘要；总长度有上限：玩家约 12k 字，主持人约 20k 字，超出时丢弃最旧的）→ `【本次唤醒】`（每个 `reasons` 信封一行，可读的中文）。
`inject_message` 只含新增的可见条目和新的唤醒原因。`seen_seq` 是文本里包含的最后一个账本 seq（没有新条目时取 `world.seq`）。
接近窗口上限（上下文字数超过阈值）时，状态板顶部加一句“上下文偏长，请调用 compact_context”。

### 4.3 系统提示词

玩家：`prompts/participant.md` 的模板（变量：`name`、`seat`、`id`、`persona`、`rules`）+ 剧本 `rules_text`。
主持人：`prompts/moderator.md` + 剧本 `rules_text` + `manual_text` + 工具使用要点（由提示词文件承担，不写在代码里）。
`no_tool_nudge`：本次运行里第一次出现“有正文但没有任何工具调用”时返回提示（“你的正文不会发送到任何频道；要发言请调用 speak，不想做任何事请调用 wait”）；之后返回 `None`。

阅读顺序：`docs/v0.12.1-plan.md`（决策 E1–E24）→ 本节。本节**替换**：§2.6 的优先级列、§3.2（Actor 规则）、§3.3 的状态事件与看门狗、§3.4、§4 中 Brain 的部分、§8.1 / §8.2（只增不减的部分除外，见 10.6）。冻结代码已改：`app/world/types.py`（`Priority` 只有 `urgent|normal`）、`app/world/state.py`（`RequestState.share_answers/auto_close`，`FreeState` 无 `debounce_s`）、`app/world/spec.py`（`FreeDefaults` 无 `debounce_s`，旧键被忽略）、`app/world/intents.py`（`OpenLimits`、`share_answers`、`auto_close`、能力开关语义）、`app/runtime/ports.py`（Brain 协议、`ToolOutcome.sleep_s`、`WakeContext` 无 `ambient`）。

### 10.1 世界：投递、请求可见性、工具修正

**优先级与投递（world-chat：`core.py`、`chat.py`）**

1. 世界投递的**每一个** Envelope 都立刻唤醒收件人，没有 ambient，没有防抖。`urgent` 只表示“期望收件人采取行动”（`floor.granted`、`request.opened`、`challenge.resolved`、`floor.completed`、`free.advisory`、`request.closed`、`challenge.opened`、`ability.used`、看门狗），仅用于唤醒原因的排序；`interrupt=True` 的语义不变。所有原来写 `priority="ambient"` 的地方改成 `"normal"`；`core.message_priority` 删除（消息一律 `normal`）。
2. `WorldCore.deliver(target, kind, event, *, priority="normal", channel_id=None, sender=None, interrupt=False, direct=False, seq=0, **payload)`：新增 `direct`。收件人是**已出局的玩家**（`is_out`）且 `direct` 为 False 时不投递（E23）；主持人和 `ENGINE_ID` 永不过滤。**发出者不会收到自己条目的 Envelope**。出局玩家依然可以用 `entries_visible` 读历史，只是不被广播唤醒。
3. 投递目录（替换 §2.6）：

| 事件 | 收件人 | `direct` |
|---|---|---|
| `message` / `message.new`（任何频道） | 能读该频道的全部成员，除发出者 | 仅系统私聊（`channel.system`）为 ✔ |
| `floor.granted`、`floor.revoked`、`floor.paused`、`floor.frozen` | 受影响的令牌持有者（`revoked/paused/frozen` 保留 `interrupt=True`） | ✔ |
| `floor.completed`、`free.advisory` | 主持人 | – |
| `request.opened`、`request.cancelled` | 该请求的收件人 | ✔ |
| `request.answer`（**新**，仅 `share_answers`） | 其他收件人 + 主持人；载荷 `request_id, player_id, value, reason` | ✔ |
| `request.closed` | 主持人（载荷 `request_id, reason, answers, tally?, leaders?, defaulted, missing`） | – |
| `challenge.opened` / `challenge.resolved` | 主持人 / 发起人 | ✔ |
| `ability.used` | 主持人（随后公开宣言作为 `message.new` 投递） | – |
| `channel.created`、`channel.updated` | 该频道成员（除操作者） | – |
| `player.updated` | 该玩家本人（✔）、其他玩家、主持人（均除操作者） | 本人 ✔ |
| `phase.changed` | 全部玩家 | – |
| `game.started/resumed/continued`、`watchdog`、`timer.elapsed` | orchestrator / supervisor / agent 直接投递，不经过世界 | n/a |

4. `free` 讨论没有 `debounce_s` 了（`FreeState`、`defaults.free`、投递载荷都不再有）。剧本里残留的 `debounce_s` 键被 `FreeDefaults` 忽略，但请顺手从两份剧本里删掉。
5. **`open_floor` / `update_channel` 的 `limits`（统一）**：`OpenLimits` 是并集，世界按 `mode` 检查键：`turn` 只接受 `TOKEN_LIMIT_KEYS`（`max_messages, max_chars_per_message, max_chars_total, duration_s`），`free` 只接受 `FREE_LIMIT_KEYS`（`duration_s, max_messages_per_member, max_chars_per_message, max_chars_total, silence_s`）。不适用的键 → `INVALID_PARAMS`，`message` 写明“mode=free 只接受：…”。通过检查后，值再用 `FloorLimits` / `FreeLimits` 校验。`free_limits` 只是旧别名（`intents.py` 已在校验前映射到 `limits`）。`update_channel.limits` 只接受 free 的键。
6. 内部 id 改为 `N1`–`N12`（`config.yml` 的 `participants`：`id: "N3"`、`seat: "3"`、`name: "Carol"`，**不再有** `persona` 字段；座位排序用 `seat` 的自然序，`"10"` 排在 `"2"` 之后）。引擎代码（`app/world|runtime|agents|orchestrator`）里不得出现 `\bp\d{2}\b` 和 `\bN\d{1,2}\b` 字面量（中立性测试会扫描，`app/game/demo.py` 豁免）。

**请求（world-game 的 `game.py`、`board.py`、`projection.py`，本轮由 lead 实现）**

- `open_request(share_answers=true)`：`request.answered` 条目对**主持人 + 全部收件人**可见；每次作答向其他收件人和主持人投递 `request.answer`；看板里该请求多出 `share_answers: true` 与 `answers: [{"player_id","value","label","reason"}]`（座位序，当前所有答案；收件人和主持人都能看到）。`sealed` 与 `share_answers` 互斥。
- `auto_close`：`all_answered`（默认）= 全员作答即关闭；`unanimous` = 全员作答**且答案相同**才提前关闭，否则一直开到截止（期间可以改答）；`deadline` = 只在截止时关闭。`request.closed` 的 `reason` 取 `all_answered|unanimous|deadline`。
- 作答可以改（最后一次为准），这一点不变；`share_answers` 请求里每次改答都会再投递一次 `request.answer`。
- `enable_ability(holders=[…])`：只有这些人可用；省略 = 全部持有者；空列表 = `INVALID_PARAMS`。`disable_ability(holders=[…])`：这些人失去能力、其余人保持；省略 = 全部关闭。
- `RequestView`（UI，见 10.6）新增 `share_answers`、`auto_close`、`answers`（**god 视角里所有请求都带答案，包括密封的**）、`result`。

### 10.2 运行时（runtime）

文件：在 §3.1 的基础上新增 `conversation.py`；`agent.py` / `mailbox.py` / `supervisor.py` / `usage.py` / `messages.py` 按下面的规则修改。

**Actor / Worker 规则（替换 §3.2）**

1. **一切投递都唤醒。** `Agent.deliver(env)` 把信封放进 `pending`；Worker 在休眠就用 `loop.call_soon` 安排**一次**激活——同一次同步泵里投递的所有信封因此合成**一次**激活，其余不等待、没有任何定时器。不存在 ambient、防抖、`ambient_cap`。
2. **激活**（一次“运行”，`gen_id += 1`，`usage.count(…, "activations")`）：`brain.begin_run(agent)` → 取走全部 `pending` 作为 `reasons` → 若 `ConversationBook` 里没有这个 agent 的对话：`brain.start_message`（FULL）创建，否则 `brain.inject_message`（DELTA）；DELTA 返回 `None` 时回到休眠（不调用模型）→ 把结果作为 user 消息**追加**到对话 → 进入循环。
3. **对话是持久的、只追加的**：`messages = [system] + conversation.messages`。`system` 与 `tools` 在对话创建时确定并保持不变（逐字节相同，才能命中供应商的前缀缓存）。一轮 LLM 返回后，assistant 消息和它的全部工具结果在**没有任何 `await`** 的一段里追加（取消因此不会留下不成对的 tool_call）；被取消、被丢弃（`stale`）的调用**不写进对话**。
4. **循环没有轮数上限**，也没有执行深度（`AgentConfig.max_rounds`、`rounds_for`、`config.runtime.max_rounds` 全部删除）。每轮工具执行之后，如果 `pending` 非空 → `brain.inject_message` 合并注入一条 user 消息（**在途合并**，不额外等待）→ 继续下一轮。结束条件：`ToolOutcome.ends_run`（`sleep`）；或模型没有工具调用且 `no_tool_nudge` 为 `None`/已 nudge 过（等同不定时 `sleep`）。结束时如果 `pending` 又非空，立刻再激活一次。
5. **打断**不变：`interrupt=True` 且 `channel_id` / `request_id` 命中本次运行的 focus → 取消在途的 LLM 调用并丢弃，带着全部 `pending` 立刻重新激活（DELTA）；防饥饿（连续取消 2 次后第 3 次改为注入）不变。
6. **休眠定时器**：`ToolOutcome.sleep_s` → `Conversation.sleep_until = clock.now() + sleep_s`（**游戏时钟**，暂停时冻结）。Supervisor 的 tick 轮询每个 agent 的 `timer_due(now)`，到点合成 `Envelope(kind="notice", priority="normal", payload={"event":"timer.elapsed","slept_s":…})` 激活它；休眠期间有任何信封到达，定时器作废。
7. **状态只有三种**：`thinking`（LLM 调用在途）、`acting`（执行工具、或两轮之间）、`sleeping`（没有运行；对局暂停 / 结束时也是 `sleeping`）。事件 `agent.status`：`{"id","state","until"}`，`until` 为定时休眠的结束时刻（游戏时钟秒），无定时则为 `null`。**不再有 `idle` / `stopped`。**
8. **压缩由编排触发**：每次 LLM 响应后 `used = prompt_tokens + cache_read_tokens + cache_write_tokens`；`window = context_window()`（来自该 agent 的模型绑定）。`used >= compact_at * window`（默认 0.6）且本对话尚未提醒过 → 追加一条系统提示 user 消息（`COMPACT_NUDGE`：“会话已接近上限，请先调用 compact_context 生成摘要，再继续”）；`compact_context` 的 `ToolOutcome.rebuild=True` → 丢弃对话，`brain.reset_conversation(agent)`，用 `start_message` 重建。`used >= trim_at * window`（默认 0.9）仍未压缩 → 兜底裁剪：从对话最前面起，按**完整的轮**（一条 assistant 消息及其全部工具结果）删除，直到低于 `compact_at`；trace 事件 `trim`。
9. 失败与重试、`cancel_grace_s`、不泄漏任务、gen_id 失效后不提交：全部不变。重试时对话保持原样。
10. 并发闸门：`llm_concurrency` / `llm_concurrency_per_provider` 为 `0` 表示不限（默认）；LLM 超时 `llm_timeout_seconds` 保留（可靠性）。

**`ConversationBook`（`conversation.py`，由 orchestrator 持有，每局一个）**：`Conversation{system, tools_sig, messages, seen_seq, sleep_until, last_input_tokens, epoch}`；`ConversationBook.get(agent_id)`、`put`、`reset(agent_id=None)`、`dump()/load()` 不需要（存档不保存对话）。构造 `Supervisor(…, book=…)` / `Agent(…, book=…)`；orchestrator 在暂停→继续时复用同一个 book（对话和 `sleep_until` 因此保留），在新局、导入、从存档恢复时 `book.reset()`。`Brain` 实例也由 orchestrator 持有，跨暂停继续复用。

**看门狗（替换 §3.3 对应部分）**：静止时仍唤醒主持人；连续 `max_watchdog_wakes` 次无进展 → `on_stall(reason: str)`；之后 seq 前进 → `on_stall(None)`。**不再自动 `hold_game`**（orchestrator 只显示警告横幅）。

**用量与预算钩子**：`UsageBook` 记四类 token（见 10.3）；`UsageBook.on_record: Callable[[str, LLMResponse], None] | None`，每次 `record_llm` 之后同步调用（orchestrator 在里面检查预算）；`count(..., "activations")`。`agent.metrics` 事件见 10.6。

**配置（`config.yml` → `runtime:`）**：删除 `debounce`、`max_rounds`；`llm_concurrency`、`llm_concurrency_per_provider` 默认 `0`；新增 `compact_at: 0.6`、`trim_at: 0.9`；保留 `llm_timeout_seconds`、`tick_interval`、`watchdog`、`max_watchdog_wakes`。

### 10.3 LLM 用量、价格、价格源（lead）

- `LLMResponse`：`prompt_tokens` 改为**未命中缓存的输入**；新增 `cache_read_tokens`、`cache_write_tokens`；价格快照新增 `cache_read_price_per_m`、`cache_write_price_per_m`（已按“空 → 输入价”解析成数字）。`cost = (prompt·in + cache_read·cr + cache_write·cw + completion·out) / 10⁶`。
- `UsageBook`：总量与 `by_model`、`by_actor` 都含 `calls, prompt_tokens, cache_read_tokens, cache_write_tokens, completion_tokens, cost_usd`；`by_actor` 另有 `activations, tool_calls, thinking_rounds, rejections`；`total_tokens` = 四类之和；`cache_hit_rate = cache_read / (prompt + cache_read + cache_write)`（总量和每个 agent 都有）。
- `ModelEntry`（`app/providers/models.py`）：`id, input_price_per_m, output_price_per_m, cache_read_price_per_m: float|None, cache_write_price_per_m: float|None, context_window_tokens, price_source: str`（`"manual"` 或 `"litellm:<key>"`）。旧数据迁移：新字段为空、`price_source="manual"`。
- 价格源：`GET /api/pricing/source` → `{"url","default_url","fetched_at","entries":n,"error":null|str}`；`PUT /api/pricing/source` `{"url"}`；`POST /api/pricing/refresh`；`GET /api/pricing/match?provider_id=&model_id=` → `{"matched":bool,"key":str|null,"input_price_per_m","output_price_per_m","cache_read_price_per_m","cache_write_price_per_m","context_window_tokens"}`。拉取模型列表的响应里，每个模型多一个 `suggested`（同上字段，或 `null`）。
