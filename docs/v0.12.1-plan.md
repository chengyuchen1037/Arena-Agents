## 0. 目标与原则

v0.12 搭好了 Actor + Worker 的骨架，但运行时里混进了"省钱设计"：

- 防抖：normal 级消息要等 1.5 秒再唤醒。
- ambient 缓存：别人在队列里发言时不唤醒任何人。
- 轮数上限：按执行深度取。
- 每次唤醒从零重建上下文：前缀缓存几乎命中不了。

结果是 agent 大部分时间什么都不做，和非异步的 v0.11 没有本质区别。

v0.12.1 的核心原则：

1. **引擎和运行时不做任何省钱限制。** 每条注入 Actor 的消息都会立刻激活 Actor，所有相关 Actor 同时被激活。狼人可以随时考虑拍刀，白狼王可以随时考虑自爆。
2. **token 管理靠 Actor 与 Worker 的编排来做，不靠少调用。** 具体手段：
   - 持久会话 + 前缀缓存（每个 agent 的对话只追加，不每次重建）；
   - 在途合并（Worker 调用期间到达的消息，在下一轮边界合并成一次注入）；
   - 只在"焦点失效"时打断；
   - 压缩时机的设计，尽量减少缓存失效次数。
3. **花多少钱由用户决定。** 引擎内部没有费用熔断，也没有轮数上限；只有用户在界面上设置的 token / 费用上限，以及"达到上限后强制停止"的开关。
4. **计费必须真实。** 区分未命中输入、缓存读取、缓存写入和输出四种价格，价格从价格源自动填写。

## 1. 决策记录（E1–E20，待你确认后冻结）

| # | 决策 |
|---|---|
| E1 | **每条注入都激活 Actor。** 删除 ambient 优先级和防抖。所有对某 agent 可见的新条目都是"激活"事件。Worker 休眠时立刻唤醒；Worker 运行时，在下一轮边界把期间到达的全部消息合并成一次注入（不额外等待）。agent 自己产生的条目不激活自己。 |
| E2 | **agent 只有三种状态：思考 / 执行 / 休眠。** "空闲""已停止"不再作为状态显示；对局暂停时所有 agent 都处于休眠，界面另有对局状态标识。 |
| E3 | **新增 `sleep(seconds?)` 工具，取代 `wait`。** 不带参数时，休眠到有新消息或新状态为止；带参数时，到点没有新消息也会醒来，便于自主规划。模型不调用任何工具时，视为不定时休眠。 |
| E4 | **删除执行深度和轮数上限。** 一次激活内 Worker 可以无限轮"模型调用 → 工具"，直到调用 `sleep`。界面去掉"执行深度"下拉框，config 去掉 `max_rounds`。模型的思考深度继续在绑定里按角色设置。 |
| E5 | **持久会话 + 前缀缓存。** 每个 agent 维护一份只追加的对话：系统提示词、工具 schema、静态设定放在不变的前缀里，之后每次激活只追加增量（新条目和状态变化）。暂停后继续时会话保留；从存档恢复或进程重启后才重建一次。 |
| E6 | **压缩由编排触发。** 会话长度超过所用模型上下文窗口的 60% 时，由 Worker 生成摘要，替换较早的部分。一次压缩只造成一次缓存失效，然后前缀重新稳定。agent 也可以主动调用 `compact_context`。 |
| E7 | **打断策略不变。** 只有让当前工作失效的事件才打断（发言权被收回、请求被取消、能力冻结了正在发言的频道），其余新消息都走注入。打断后，Worker 未完成的那次调用丢弃，不写进会话。 |
| E8 | **并发闸门默认不限。** 全局并发和每个 Provider 的并发默认等于 agent 数。闸门只用来应对 Provider 的速率限制（429 时退避重试），不用来省钱，可在 config 里调整。 |
| E9 | **看门狗只唤醒主持人，不再自动暂停。** 对局静止时照常唤醒主持人；连续唤醒仍无进展时，只在界面上显示警告横幅，由用户决定是否暂停。 |
| E10 | **用户预算上限。** 右上角 token 统计旁新增"上限"按钮，可以设置本局的 token 上限和/或费用上限，以及"达到上限后强制停止"开关。达到 80% 时显示提醒；达到 100% 时，勾选了就暂停对局（原因：预算），没勾选就只提醒。默认值保存在工作区设置里。 |
| E11 | **四种价格。** 每个模型有 `input`（未命中缓存）、`cache_read`、`cache_write`、`output` 四个价格（美元 / 每百万 token）。用量解析区分这四类，并在每次调用时记录价格快照。缓存价格为空时，按输入价格计。 |
| E12 | **价格源。** Provider 设置里新增"价格源 URL"（全局一个，默认值为 `https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json`）。拉取模型列表后，按模型 id 自动匹配并填好四个价格和上下文窗口；用户可以再改。界面显示每个价格是从哪个键匹配来的。 |
| E13 | **固定编号与名字。** 内部 id 统一为 `N1`–`N12`（替换 `p01`–`p12`），编号即座位号 1–12。默认名字是 Alice、Bob、Carol、David、Eve、Frank、Grace、Henry、Ivy、Jack、Kate、Leo（不带数字）。给模型看的文本写作 `N3 Carol`，界面上只显示 `Carol`。 |
| E14 | **名册持久化。** 名字、头像、性格设定、记忆按座位号保存在工作区的名册里，跨对局不变。用户在开局前（对局未开始时）可以改名字（名字必须唯一）和重新生成头像；改完下次打开依然保留。每局开局时把当时的名册快照存进存档。 |
| E15 | **像素头像。** 头像由程序化素材库随机组合：脸型、肤色、发型、发色、眼睛、表情、配饰都由算法生成。头像以"组合描述"的形式保存，渲染结果是确定的。可以重新生成全部头像，也可以只重新生成某个玩家的。主持人用固定图标。 |
| E16 | **性格与记忆。** 每名玩家有两段设定，默认为空：<br>• **性格设定**：说话风格、思维方式。<br>• **记忆**：对其他玩家的印象，以及自己玩狼人杀的"经验"（常输、常赢、胜率高等）。<br>两段都放进系统提示词的静态前缀里（因此可以被缓存）。每段旁边有"用主持人模型完善"按钮，把要点扩写成完整设定，结果先给用户确认再保存。 |
| E17 | **身份标签优先。** 玩家卡片的主标签永远是身份（在当前视角下可见时）。警长等状态显示为卡片上的小徽章，不再占用主标签位。 |
| E18 | **请求进入信息流。** 请求的发出、作答进度和结果，作为卡片显示在信息流里：上帝视角看全部，玩家视角只看与自己有关的请求。 |
| E19 | **狼人商议改为固定流程**（写进主持人手册，靠工具支持实现）：<br>1. 开场：宣布本轮时长，同时向所有存活狼人发出**不密封的组内确认请求**。狼人可以随时提交或修改刀口（即"拍刀"），组内互相可见当前每人的选择。<br>2. 到时或冷场时，主持人在频道里催促一次。<br>3. 全员一致就收口；不一致就再商议一轮短时间，之后按多数决定，平票由座位最前者决定。<br>4. 主持人在狼人频道公布"今晚刀口：X"。 |
| E21 | **复盘默认手动。** 对局结束后不自动复盘。终局后出现"复盘"按钮（全部玩家一起，或在玩家详情里单独复盘）：<br>• 引擎把本局战绩（身份、阵营、胜负）写进该玩家记忆文件的【战绩】段，并重新计算场次、胜率、各身份胜率；<br>• 该玩家用自己绑定的模型写一段复盘（对其他玩家的印象、自己的得失），追加到【对局记忆】段。<br>复盘的费用计入本局用量。同一局对同一玩家只能复盘一次，界面显示"已复盘"。 |
| E22 | **预算上限按本局计。** 新建对局时用量从 0 开始，上限的默认值取自工作区设置；终局后继续、手动复盘产生的用量也计入本局。 |
| E23 | **出局玩家不激活。** 广播类消息（频道发言、公告、状态变化）不再激活已出局的玩家（按剧本的 `ui.out_tags` 判断）。只有**直接发给他本人**的事件才激活他：发给他的请求（例如猎人开枪、警徽移交）、给他的发言权（例如遗言）、主持人发给他的私聊。复活（`update_player` 去掉出局标签）后恢复正常激活。 |
| E24 | **记忆的统一管理。** 名册菜单提供四项操作，对局未开始时可用：<br>• **导出全部记忆**：把 12 人的性格和记忆打包成一个 `.zip`；<br>• **导入记忆包**：一次性加载全部或部分玩家的记忆，导入前预览将被覆盖的内容；<br>• **清除全部记忆**：二次确认，可以选择是否同时清除性格设定；<br>• **本局加载记忆**开关：默认开启；关闭后，本局的系统提示词不包含记忆段，文件本身不受影响。 |
| E25 | **请求新增 `share_answers` 与 `auto_close`**（E19 的实现手段）：`share_answers` 让收件人实时看到彼此的答案；`auto_close=unanimous` 让请求只在全员答案一致时提前关闭，否则一直开到截止，期间可以改答。狼人商议用它实现“拍刀，直到一致才进入下一个环节”。 |
| E26 | **主持人也有随机头像。** 主持人不是座位，没有名字 / 性格 / 记忆可设，但和玩家一样有一个由素材库随机组合的像素头像。名册里多一个 `moderator` 条目；“重新生成全部”把 12 个座位和主持人一起挑（13 个头像两两至少 3 项素材不同），也可以在主持人详情里单独重新生成；本局的主持人头像在创建对局时复制进存档，本局内不变。固定的礼帽图标只在后端没有给出头像、或素材库缺失时回退。 |
| E20 | **存档格式升到 v4。** v0.12.0 的存档（使用 p01 id、旧计费字段）不能打开，和 D3 一致：保留在列表里，不修改。 |

## 2. 运行时：Actor 与 Worker 的编排（核心）

### 2.1 激活流程

```text
世界提交一个条目 → 按可见性投递 Envelope 给每个能看到它的 agent
                     （发出者本人除外；已出局的玩家只接收直接发给他的事件，见 E23）
        │
Actor（每个 agent 一个，永远在线）
  ├─ Worker 在休眠 → 立刻激活：开始一次运行，注入内容 = 这条 Envelope
  ├─ Worker 在思考 / 执行
  │     ├─ Envelope 让当前焦点失效（E7）→ 取消当前调用，带上全部待处理内容立即重启
  │     └─ 否则 → 放进"待注入"，在下一轮边界（当前调用返回、工具执行完之后）
  │              一次性合并注入，然后继续下一轮
  └─ 定时器到点（sleep(seconds)）→ 激活，注入内容 = "定时醒来" + 期间的状态变化
```

- **不额外等待。** 没有防抖，也没有缓冲。合并只发生在"Worker 正忙"时，这正是编排带来的自然批处理。
- **"思考次数""工具调用次数""激活次数"都按 agent 实时累计**，供界面显示。

### 2.2 持久会话（为前缀缓存设计）

每个 agent 的会话结构：

| 位置 | 内容 | 变化频率 |
|---|---|---|
| system | 角色提示词 + 剧本规则（主持人另加手册）+ 名字、编号 + 性格设定 + 记忆 | 只在开局时生成（名册在对局中不可改） |
| tools | 工具 schema（顺序固定） | 不变 |
| 第 1 条 user | 开局状态板 + 身份说明 | 开局一次 |
| 之后 | 交替追加：注入（新条目 + 状态板**变化部分**）/ assistant（含工具调用）/ 工具结果 | 只追加 |

- **状态板改为"变化部分"注入。** 每次注入只写发生变化的字段（发言权、待答请求、标签、阶段等），不重复整块状态板，前缀因此保持稳定。
- **Anthropic 需要显式缓存断点。** 适配器自动在 system、tools 和最近一条消息上加 `cache_control`（最多 4 个断点）。OpenAI 和 DeepSeek 是自动前缀缓存，不需要改请求格式。
- **持久化。** 会话保存在编排器内存里，暂停后继续直接复用。存档只保存账本和世界状态；从存档恢复后，会话按账本重建一次（每个 agent 一次缓存未命中）。
- **压缩（E6）。** 超过阈值时，Worker 先用当前会话生成摘要，再把会话替换成：前缀 + 摘要 + 最近 N 轮。

### 2.3 删除和保留

| 删除 | 保留 |
|---|---|
| ambient 优先级、防抖、`ambient_cap` | urgent 打断（焦点失效时） |
| `max_rounds`、执行深度、`rounds_for` | 防饥饿：连续被取消 2 次后，第 3 次改为注入 |
| 每次运行重建上下文（`start_message` 改为只在会话创建时调用） | gen_id、提交闸门、`STALE` 校验 |
| 看门狗自动暂停 | 看门狗唤醒主持人、LLM 超时与重试（可靠性，不是省钱） |

### 2.4 预算上限（E10）

- 每次 LLM 调用记账之后，编排器检查本局累计的 token 和费用是否达到上限。
- 达到 80%：推送 `budget.warning` 事件，界面显示横幅。
- 达到 100%：勾选了"强制停止"就 `pause("budget")`（暂停原因写清楚），提高上限或取消勾选后才能继续；没勾选就只推送 `budget.reached` 并显示。
- 引擎本身不做任何其他限制。

## 3. 计费（E11、E12）

### 3.1 模型价格字段

```text
ModelEntry:
  id, context_window_tokens
  input_price_per_m          未命中缓存的输入
  cache_read_price_per_m     缓存读取（为空 = 按 input 价）
  cache_write_price_per_m    缓存写入（为空 = 按 input 价；目前只有 Anthropic 计费）
  output_price_per_m         输出（含推理 token）
  price_source               例如 "litellm:deepseek/deepseek-chat" 或 "manual"
```

已保存的旧 Provider 自动迁移：新增字段为空，`price_source="manual"`。

### 3.2 用量解析（逐个适配器）

| 协议 | 未命中输入 | 缓存读取 | 缓存写入 | 输出 |
|---|---|---|---|---|
| OpenAI Chat | `prompt_tokens − cached` | `prompt_tokens_details.cached_tokens`；DeepSeek 用 `prompt_cache_hit_tokens` | 0 | `completion_tokens` |
| OpenAI Responses | `input_tokens − cached` | `input_tokens_details.cached_tokens` | 0 | `output_tokens` |
| Anthropic | `input_tokens` | `cache_read_input_tokens` | `cache_creation_input_tokens` | `output_tokens` |

- `LLMResponse` 新增 `cache_read_tokens` 和 `cache_write_tokens`；`prompt_tokens` 改为"未命中输入"。
- 价格快照包含全部四个价格。
- `UsageBook` 按 agent 和按模型分别累计四类 token 与费用，并新增"缓存命中率"。

### 3.3 价格源

- **在哪里设置。** Provider 弹窗顶部有"价格源 URL"输入框（默认 litellm 的 JSON）和"刷新价格表"按钮。
- **怎么拉取。** 由服务端拉取，只允许 https；校验规则和 Provider URL 相同，屏蔽内网和元数据地址；设置 20 MB 大小上限。拉取结果连同时间戳缓存到工作区。
- **怎么匹配。** 依次尝试：
  1. 完全相同的键；
  2. `<litellm_provider>/<模型 id>`（根据 Provider 的 base_url 推断，例如 deepseek、openai、anthropic）；
  3. 去掉日期后缀；
  4. 不区分大小写。
- **字段换算。** `input_cost_per_token`、`output_cost_per_token`、`cache_read_input_token_cost`、`cache_creation_input_token_cost` 乘以 10⁶；`max_input_tokens` 作为上下文窗口。实现前先抓一次真实文件核对字段名。
- **界面行为。** 拉取模型列表之后自动填好价格，每个价格旁显示来源键，用户可以再改；匹配不到就留空并提示手动填写。

## 4. 名册、头像、性格与记忆（E13–E16）

### 4.1 名册文件（工作区内的明文文件，可以在外部直接编辑）

```text
<工作区>/roster/
  roster.json        [{seat:1, id:"N1", name:"Alice", avatar:{...组合描述}}, ...]
  N1.persona.md      性格设定（默认为空）
  N1.memory.md       记忆（默认为空），分三段：【战绩】（引擎维护）【对局记忆】【经验与印象】
  ...
```

- 工作区关闭时放在数据目录下的 `roster/`。
- 写入方式：原子写入，写后校验。
- API：`GET /api/roster`、`PUT /api/roster/{seat}`（名字、头像，只允许在对局未开始时修改）、`PUT /api/roster/{seat}/persona|memory`、`POST /api/roster/{seat}/avatar:regenerate`、`POST /api/roster/avatars:regenerate`、`POST /api/roster/{seat}/refine`（`kind=persona|memory`，用主持人绑定的模型扩写，返回草稿，用户确认后才保存；费用计入工作区的"非对局用量"）。
- 记忆统一管理（E24）：`GET /api/roster/memory:export`（返回 zip）、`POST /api/roster/memory:import`（先 `dry_run=true` 返回将被覆盖的差异，确认后再导入；限制大小，只接受名册内的文件名）、`POST /api/roster/memory:clear`（`include_persona` 可选）。本局是否加载记忆是对局设置，存进存档。
- 复盘（E21）：`POST /api/game/review`（`seats` 省略表示全部），只在对局结束后可用；每个座位一局只能复盘一次；返回每人的进度，结果通过 SSE `review.*` 事件推送。

### 4.2 像素头像生成

- **画布。** 20×20 像素，2 像素深色描边，渲染时放大 3–6 倍，使用 `image-rendering: pixelated`。
- **素材全部由算法生成。** 用 `tools/avatar_lab.py` 生成，产物 `static/avatar/parts.json` 提交进仓库：

| 素材 | 生成方式 | 数量（目标） |
|---|---|---|
| 脸型 | 参数化轮廓（圆、方、尖下巴、宽脸、圆脸短下巴…），左右对称 | ≥ 8 |
| 肤色 | 多档调色板（浅到深 + 奇幻色），每档含亮部、暗部 | ≥ 10 |
| 发型 | 轮廓函数（短发、长发、卷发、刘海、马尾、爆炸头、光头…）加随机扰动，左右对称后再加不对称的发梢 | ≥ 30 |
| 发色 | 调色板（自然色 + 鲜艳色），每色 3 级明暗 | ≥ 14 |
| 眼睛 / 表情 | 小模板加变体（睁眼、眯眼、闭眼、眨眼；嘴型：笑、平、张嘴、坏笑；腮红） | ≥ 20 |
| 配饰 | 帽子、头巾、眼镜、墨镜、耳机、头箍、发卡、角、光环、面具… | ≥ 24（含"无"） |

- **质量过滤。** 自动丢弃以下组合：发色和肤色太接近、配饰遮住眼睛、脸部可见像素过少、轮廓不封闭。
- **组合描述。** `{face, skin, hair, hair_color, eyes, mouth, accessory, accessory_color}`；同一描述在任何地方渲染结果都相同。
- **随机选取。** 重新生成时随机组合；同一名册里的 12 个头像两两至少有 3 项素材不同。
- **前端渲染。** `static/js/avatar.js` 用 canvas 绘制并缓存成 dataURL。
- **先出样张再接入。** 开发时先生成一张约 120 个头像的样张，给你确认风格之后再接入界面。

### 4.3 进入游戏

- **开局快照。** 开局时把名册（名字、头像、性格、记忆）拷进存档，本局内不再变化，保证可复现，也保证前缀缓存稳定。
- **系统提示词新增两段。** 【你的性格】和【你的记忆与经验】，内容为空时整段省略；"本局加载记忆"关闭时，记忆段一律省略（E24）。
- **战绩统计。** 由引擎根据存档计算，只在复盘时写入记忆文件（E21），不会自动写入。

## 9. 测试方案

### 9.1 离线单元与集成测试（pytest，全部不联网）

**运行时（`tests/v12/runtime/`）：**
- **立即激活。** 休眠的 Worker 收到任意新消息后立即开始运行，测试断言激活延迟 < 50 ms，没有防抖。
- **在途合并。** Worker 调用期间到达 N 条消息，在下一轮边界只注入 1 次，并且包含全部 N 条，顺序与账本一致。
- **不激活自己。** 自己产生的条目不会激活自己。
- **全员同时激活。** 一条公共消息会同时激活所有能看到它的存活 agent（12 名玩家加主持人，减去发出者）。
- **出局玩家（E23）。** 出局玩家不被广播类消息激活；发给他的请求、遗言发言权、主持人私聊能激活他；复活后恢复正常激活。
- **没有轮数上限。** 脚本化模型连续 50 轮都调用工具也不会被截断，直到调用 `sleep` 才结束。
- **`sleep(seconds)` 定时器。**
  - 到点醒来；期间有新消息就提前醒来，定时器作废。
  - 暂停时定时器冻结，继续后接着计时。
- **持久会话。**
  - 第二次激活的请求消息是第一次的严格前缀加增量（逐字节比较前缀）。
  - 被取消的调用不会写进会话。
  - 压缩之后，前缀等于"system + tools + 摘要"，之后又恢复只追加。
- **打断、防饥饿、gen_id**：沿用现有测试，按新模型改写。
- **看门狗只告警。** 连续无进展时推送警告事件，不会暂停对局。
- **预算（E10、E22）。** 80% 时推送提醒；100% 时，勾选了强制停止就暂停（原因是 budget），没勾选就只提醒；提高上限后可以继续。新建对局时用量归零；终局后继续和手动复盘的用量计入本局。

**计费（`tests/test_pricing.py`、`tests/test_llm_usage.py`）：**
- **用量解析。** 三种协议各用录制好的响应样本，解析出四类 token；DeepSeek 用 `prompt_cache_hit_tokens` 的变体。
- **费用公式。** 按四个价格计算；缓存价格为空时回落到输入价格；价格快照不受之后改价影响。
- **价格源。** 用一份裁剪过的 litellm JSON 作为夹具：
  - 四种匹配规则逐一覆盖；匹配不到时留空；
  - 单位换算正确；
  - 非 https、内网地址、超过大小上限、JSON 格式错误时都安全失败。
- **旧数据迁移。** 旧 Provider 数据迁移后可读，新增字段为空，来源为 manual。
- **Anthropic 缓存断点。** 请求体里 `cache_control` 的数量不超过 4，位置正确。

**名册与头像（`tests/test_roster.py`、`tests/test_avatar_lab.py`）：**
- **名册默认值与持久化。** 默认 12 个名字；改名后重启仍然保留；名字重复、为空或过长时拒绝；对局运行中不允许修改。
- **性格与记忆文件。** 读写、原子写入；在外部手工修改后能读到新内容；内容为空时提示词省略整段。
- **"用主持人模型完善"接口。** 用假模型测试：返回草稿，不会自动保存；费用计入非对局用量。
- **开局快照。** 开局后修改名册，不影响进行中的对局。
- **记忆统一管理（E24）。**
  - 导出的 zip 再导入后内容逐字节一致；
  - 导入预览列出将被覆盖的玩家与差异；路径穿越、超大文件、名册外的文件名都被拒绝；
  - 清除全部记忆后文件为空；选择"同时清除性格"时性格也被清空；

## 10. 风险

| 风险 | 应对 |
|---|---|
| 全员激活后，调用量和 token 会比 v0.12 高一个数量级 | 这是刻意的设计（原则 1）；用持久会话加前缀缓存压低单价；预算上限由用户掌控 |
| 自由讨论中可能出现连锁反应：一条消息激活所有人，所有人再发言 | 条数限制和发言权由世界规则约束；主持人可以随时收回发言权 |
| Provider 速率限制（429） | 退避重试；并发闸门可以在 config 里下调 |
| 持久会话越来越长 | 编排触发压缩（E6）；每次压缩只造成一次缓存失效 |
| 程序化头像质量不稳定 | 质量过滤加人工确认样张（第 8 节的检查点） |
| 价格源格式变化 | 解析失败时保留旧价格并提示；可以改成别的价格源 URL |

## 12. 实施记录（交付时补充：与方案不一致、或方案之外的地方）

状态：已实现，验收清单（§9.4）逐项核对过；验证数据见发布说明与交付报告。

| 项 | 方案 | 实际 | 原因 |
|---|---|---|---|
| 头像描边 | 2 像素 | 1 像素（深紫 `#2a1b3d`），下巴和发梢处靠暗部加重 | 20×20 的画布上 2 像素描边会吃掉一半的脸 |
| 眼睛颜色 | 未规定 | 深色瞳孔，外加红眼 / 粉眼 / 爱心眼 | 契约的固定色板没有"虹膜色"；要绿眼、蓝眼需要在契约里加 `fixed.iris` 并在 `avatar.js` 加一行映射 |
| **主持人头像（E26，新增）** | 固定的礼帽图标 | 和玩家一样随机组合；名册里多一个 `moderator` 条目（只有头像，没有名字 / 性格 / 记忆可设）；“重新生成全部”把 12 个座位和主持人一起挑（13 个两两不同）；固定礼帽只在后端没给头像或素材库缺失时回退 | 用户在验收时提出（契约 §10.9） |
| 压缩 | 60% 提醒、90% 裁剪 | 同左；另加：由 `compact_context` 重建出的对话，只有比刚重建时又增长了窗口的 10% 才会再次提醒 | 开局信息本身超过阈值时（小窗口模型），重建释放不了空间，会陷入“压缩—重建—再压缩”（真实模型实测：12000 token 窗口下，主持人压缩 16 次 → 2 次，缓存命中率 85% → 92%） |
| 记忆导入 / 清除 / “本局加载记忆”开关 | 对局未开始时可用（E24） | 界面按 E24（导出随时可用）；API 本身不限制，已开始的对局保持开始时的副本 | 避免对局中途误操作，同时不让 API 变得难用 |
| 开局快照 | 开局时把名册拷进存档 | 名字 / 头像在创建对局时复制；性格 / 记忆在点“开始”时再读一次文件（它们是纯文本，可能在应用外被编辑）；已开始的对局保持开始时的副本 | 让“外部编辑文件，然后开始”按预期生效 |
| 一次性调用的用量（“完善”、复盘） | 计入工作区的“非对局用量” | 计入当前对局的用量（顶栏数字、预算上限都包含），并通过 `agent.metrics` 事件推送（“完善”用伪角色 `roster`） | 顶栏数字要与服务端合计一致（实时回放检查发现的漂移） |
| 一次性调用的 `max_tokens` | — | 6000 | 推理模型的思考也算进上限，2000 会被思考耗尽 |
| `GET /api/roster` | `seats` | 另有 `moderator` | E26 |
| 工作区不可用时的名册 | — | 只读默认值，不创建任何文件；所有写操作返回“工作文件夹不可用” | 避免名册写进旧的全局目录 |

已知限制：

- 玩家视角下，其他玩家只显示**公开**标签（沿用 v0.12.0 的规则），所以狼人视角看不到队友的身份标签（队友名单在狼人频道里由主持人公布）。
- 头像的脸型基本是人头（没有机器人 / 史莱姆那类“非人”造型），眼睛没有绿 / 蓝虹膜；描边 1 像素。
- 全员激活使调用量和 token 比 v0.12 高一个数量级（刻意的设计，靠持久会话与前缀缓存压低单价；上限由用户掌控）。
- 价格源按 LiteLLM 表里的条目名匹配，找不到或不准时可以手动改；改过价格的模型会标记为“手动”。
- 工作区模式没有在真实浏览器里端到端走过（本环境不允许在项目目录之外创建文件夹）；用真实的 `workspace` 模块做了进程内的集成测试（`tests/test_roster_workspace.py`：名册位置、重启后保留、切换工作区、不可用时不落盘）。
