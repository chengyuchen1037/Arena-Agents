# Bot：名字、头像和四层记忆（v0.14）

> 决策见 [v0.14 方案](v0.14-plan.md)（H1–H59）；接口与载荷见 [实现契约](v0.12-contracts.md) §13（**代码是权威**）；数据目录与存档里的 bot 见 [storage.md](storage.md)、[archive.md](archive.md)。本页讲**怎么用、怎么改、怎么写一个新的**；每个数字（字数上限、秒数）都来自 `app/bots/types.py`。

v0.14 之前，一个玩家就是一个座位：名字、性格和记忆挂在 `N1`–`N12` 上，整局所有座位共用一套提示词。v0.14 里**玩家是 bot**：

- **bot = 名字 + 头像 + 分层记忆 + 初始化记录。** 座位只是“这一局坐在哪里”：开局前可以拖动卡片换座，bot 的记忆和模型不受影响。
- **同一个模型也能有不同的风格。** 每个 bot 有自己的底层设定（怎么说话、怎么分析）；它在对局之外自己读契约和规则、写下自己的理解（**初始化**），打完之后自己复盘（**复盘**）。
- **引擎不替 bot 说话。** 发言只来自 bot 自己的 worker：它可以多轮思考，再自己调用 `speak`。不合格的发言（太长、读起来像报告）只被**退回**，由它自己重写，从不被截断或改写。
- 主持人不是 bot：它仍是原来的主持人 agent（只有一个随机头像）。
- **本版固定 12 个玩家位。** 想要一个新 bot：改掉桌上某个玩家（改名、换头像、写它的底层设定），或者导入一个 `.arenabot` / 默认库里的 bot 去覆盖它（[§10](#10-arenabot交换一个-bot)、[§9](#9-默认库与-v013-迁移)）。

## 1. 四层记忆

| 层 | 是什么 | 谁写 | 存在哪 | 什么时候被读 |
|---|---|---|---|---|
| **L0 底层设定** | 身份、说话方式、分析方式（另有最多 3 个附加分区） | **只有你**：编辑器、导入 `.core.md`、默认库、采纳复盘的提案 | bot 目录的 `core/` | 系统提示词的最前面，**一字不删**；末尾再用一两句话提醒一遍 |
| **L1 架构** | ① 官方契约（全局一份：平台怎么运作）② bot 自己的操作笔记 | ① 你（导入 / 恢复默认）② bot（初始化写，复盘修订；你也能改） | ① `contract/` ② bot 的 `arch/notes.md` | 契约的“必读”段和操作笔记挂进系统提示词；“参考”段在对局中用 `read_contract` 查 |
| **L2 规则** | ① 官方剧本（规则）和可选的学习材料 ② bot 自己的规则要点、打法、待解问题，对其他玩家的印象，战绩 | ① 你 ② bot（初始化 / 复盘写；你也能改）；战绩由引擎累加 | ① `rules/` ② bot 目录 | 规则要点和把握够高的打法挂进系统提示词；带标签的打法在关键时刻被提醒 |
| **L3 对局** | 状态板、硬事实台、可见历史、笔记 | 引擎，以及 bot 自己（笔记、`jot`） | 对局存档 | 每一次被唤醒 |

几条设计上的约定：

- **bot 自己写的都是假设。** 要拿以后对局的结果检验：被支持就加强，被推翻就改。提示词里**不教打法**——契约只讲平台怎么运作，规则来自剧本，打法是 bot 自己写出来的。
- **L0 只有你能改。** bot 在复盘里最多“提议”改它，由你采纳或拒绝（[§8](#8-复盘)）。
- **一局之内记忆冻结。** 开局那一刻拍一份快照，局中 bot 只能写 L3 笔记和 `jot`（留给复盘的线索）；暂停、继续、重启后恢复一局，都用快照重建提示词，**不读当前文件**。所以在对局进行中改某个 bot 的文件，影响的是下一局。
- **没有回滚、没有历史版本。** 复盘的写入、你的编辑都直接生效；想纠正就在详情里直接改或清除，想留底就先导出 `.arenabot` 或总存档。

> **两个 `bots/`，别混了。** 仓库里的 `bots/` 是**默认库**（12 个模板，见 [bots/README.md](../bots/README.md)）；数据目录里的 `data/bots/` 才是**你的** bot。首次运行把前者复制成后者，之后改前者不会影响已经在用的玩家。

## 2. 快速上手：写一个新 bot

1. **点一个玩家的卡片**打开详情。改名字、换头像只能在对局未开始时做；没有初始化过的 bot 改名不会弹窗（[§7.3](#73-冻结改名与清除)）。
2. **写底层设定**（[§3](#3-l0底层设定)）：详情里的“底层设定”编辑器，每个分区有字数计数；或者在 ⚙ 设置 ② 里导出 `.core.md`、用任何编辑器改完再导入；也可以写几句要点，点“用主持人模型完善”生成草稿（草稿不会自动保存，要你确认）；还可以从默认库导入一个现成的做起点。
3. **绑定模型。** 每个 bot 用自己的模型：初始化、对局、复盘用的都是这个绑定。拖动座位不会改变它。
4. **初始化**（[§7](#7-初始化)）：玩家详情里的“初始化”，或参与者栏的“⚙ 全局初始化”。它读契约和规则，写下自己的操作笔记、规则要点和打法，最多 120 秒。
5. **看一眼它写了什么**，不满意直接改（你的编辑直接生效，不影响初始化状态）。
6. **开局。** 开局检查会拦下还没准备好的 bot，并按玩家列出要做什么（[§7.2](#72-状态与开局检查)）。
7. **终局后复盘**（[§8](#8-复盘)）：看每个 bot 改了什么，处理“待确认”里的底层设定提案。
8. **分享**：详情里导出 `.arenabot`（[§10](#10-arenabot交换一个-bot)）。

## 3. L0：底层设定

### 3.1 三个必需分区，最多三个附加分区

| 分区 | 文件 | 写什么 | 上限 |
|---|---|---|---|
| 身份 | `core/identity.md` | 一两句话加一点背景：你是谁、从哪里来、想要什么（默认库里的每个 bot 都“想赢”） | 300 字 |
| 说话方式 | `core/voice.md` | 一段连贯的散文 + 3–5 句用「」标出的原话样本 + 最后一行 `篇幅：40–110 字` | 600 字 |
| 分析方式 | `core/mind.md` | 怎么看局面、信什么、被结果打脸以后怎么办 | 400 字 |
| 附加（可选） | `core/extra-<标识>.md` | 口头禅、特殊习惯之类，最多 3 份 | 每份 300 字 |

三个必需分区缺一个、或者是空的，这个 bot 就**不能初始化、不能开局**。超过上限一律被拒绝（从不替你截断），提示会点名分区和字数，例如“「说话方式」最多 600 字（现在 612 字）。”

写法建议（默认库就是这样写的）：

- **说话方式写成散文，不要分点**；原话样本别重复。篇幅区间别超过单条发言的上限（白天发言的上限是 300 字；超了会被 `TOO_LONG` 退回，具体数字以状态板为准）。`篇幅：a–b 字` 这一行有用：bot 每次轮到发言时会被提醒它，基准也用它检查有没有写偏。
- **分析方式写态度，不写具体打法。** 打法是 bot 初始化时自己写的，而且会被以后的对局修订。
- **别写具体游戏的词汇。** 游戏的内容通过剧本进来；底层设定只说“这个人是谁、怎么说话、怎么想”，同一个 bot 才能换剧本继续用。
- 一个人设就爱“一二三”地说话？在说话方式里**单独写一行** `允许口头列举`，输出闸里的“分条”检查就对它关掉（其余检查不变）。

### 3.2 合并 md（`<名字>.core.md`）

导入、导出和在编辑器里整份粘贴用的都是同一种文件：一个 front matter 加几个一级标题分区。下面是默认库里 Alice 的完整文件（导出 Alice 就得到这个）：

```markdown
---
format: arena-core
version: 1
name: Alice
---
# 身份
一个打了二十多年线下局的老玩家，从小酒馆泡到比赛场，什么花招都见过，所以对花招不太感冒。话不多，但一开口就是结论。你是来赢的，不是来陪聊的，最烦绕圈子和反复表态的人。

# 说话方式
你说话短，通常两三句就停，很少超过一百字。爱反问，喜欢直接点名，嘴上不留情面，但从不骂人，也不翻旧账。不爱铺垫，更不爱把别人已经说过的话再复述一遍；被人质疑时，你顶多回一句，不解释第二遍。偶尔冒出一句冷幽默，说完就收。
「你急什么？」「这票你自己信吗？」「我只看他投了谁。」「这话你上一轮也说过，结果呢？」
篇幅：40–110 字

# 分析方式
你先看发生了什么：谁出局了、谁投了谁、谁改了主意；然后才听谁说了什么。说得漂亮不等于是真的，话越顺，你越要拿记录去对一对。你的判断都只是暂时的，被结果打脸就认，改得很快，不嘴硬，也不事后找补。老玩家最大的本钱不是经验，而是肯认错的速度。
```

要加附加分区就再写一个 `# 附加：<标题>`：

```markdown
# 附加：口头禅
「行，听你的，出了再说。」
```

规则：

- front matter 用 `---` 包住，必须有 `format: arena-core` 和 `version: 1`；`name:` **只作提示，导入时不会改名**（名字和目标玩家不同时会提醒你）；`#` 起的行内注释会被忽略。
- 必需分区的标题固定是 `# 身份`、`# 说话方式`、`# 分析方式`；附加分区是 `# 附加：<标题>`（标识由标题生成：用标题里的 ASCII 字母、数字、`-`，没有就用 `x1`、`x2` ……）。
- 分区**内部**的二级及以下标题当正文；但**正文里不要出现 `# ` 开头的行**，它会被当成新的分区。
- 缺必需分区、分区为空、超过字数、附加超过 3 份、未知的一级标题、重复的分区，都会被整份拒绝，并把**每一处问题**列出来。
- 解析宽松、输出规范：导出的文件再导入，内容一字不差。

### 3.3 改了 L0 之后

- 已经初始化过的 bot，改了底层设定会变成 ⚠“需要重新初始化”（哈希对不上了），**记忆保留**；编辑前会弹窗提示。
- 清除底层设定（设置 ② 的“全部清除”或某一行的“清除”）后，bot 不能开局，直到你重新写好或导入。
- 想让 bot 的风格变一变，改 L0 是最直接的办法；让它“学会”什么，则是改它的记忆（[§5](#5-bot-自己的记忆)）。

## 4. 官方契约、剧本和学习材料

这些是**全局**的，所有 bot 共用，放在数据目录里：设置里的 ③ 官方契约、④ 规则管它们。

### 4.1 官方契约（L1）

- 一份 markdown，分两段：`## 必读`（**≤ 1200 字**，挂进每个 bot 的系统提示词）和 `## 参考`（对局中 bot 用 `read_contract` 按需查，可以只读某个小标题，比如“回执码”）。默认契约随程序提供（`prompts/contract.md`），首次运行时复制进数据目录。
- 契约**只讲平台怎么运作**：怎么发言、怎么休眠、回执码是什么意思、笔记怎么用。不讲打法，也不含任何游戏的词汇。
- 导入时检查：front matter（`format: arena-contract`）、两段齐全、必读段不超过 1200 字、整份 ≤ 20000 字，并且**必须提到玩家的每一个工具名和每一个回执码**——缺哪个就拒绝并列出缺项（否则 bot 会遇到契约没解释过的回执）。
- 操作：导出 md、导入 md、恢复默认。**导入或恢复默认后，所有 bot 变成“需要重新初始化”**（先弹窗告诉你）。
- 没改过的默认契约会随程序升级自动换成新的（bot 随之变 ⚠）；你导入的、或者在数据目录里手改过的，程序不会再动。

### 4.2 剧本和学习材料（L2 官方部分）

- **剧本**是一个文件：游戏机制、给玩家看的规则、只给主持人看的手册，一体导入导出（所以导入的是整份剧本；它同时决定主持人手册和游戏机制）。导入时由加载器校验，失败会指出原因。引擎从数据目录读剧本；`config.yml` 的 `scenario.path` 只是“默认来源”。
- 剧本里的 `situations:` 声明了**情境标签**（把阶段、频道、请求映射成“警上”“发言”“投票”“夜晚”“遗言”“狼队”“平票”这样的词；默认剧本就声明了这七个）。打法条目带上同样的 `#标签`，bot 就会在对应的时刻想起它（[§5.2](#52-打法playbook)）。
- **学习材料**是你放进来的补充资料：`rules/<剧本>/materials/<标识>.md`，**默认为空**。bot 只在初始化和复盘时读它（对局中不再翻资料）；`knowledge/` 目录里的资料只给主持人。每个剧本最多 20 份、每份 ≤ 100 KiB。
- 剧本或材料一变，**所有 bot 变成“需要重新初始化”**（先弹窗告诉你）。

## 5. bot 自己的记忆

在玩家详情的“记忆”里能看到、能改。每个文件都有字数计数，超限会被拒绝；你的编辑**直接生效**，也**不影响初始化状态**（只有一个例外：把操作笔记、规则要点或打法清空，开局检查会因为缺少必需文件而拦下，要重新初始化）。

| 记忆 | 文件 | 内容 | 上限 |
|---|---|---|---|
| 操作笔记（L1） | `arch/notes.md` | 它对平台怎么运作的理解：准备怎么用工具、遇到各种回执怎么办 | 800 字 |
| 规则要点（L2） | `rules/<剧本>/digest.md` | 它对这个游戏规则的理解 | 800 字 |
| 打法（L2） | `rules/<剧本>/playbook.md` | 它打算怎么玩：一条一个假设 | 20 条，每条正文 80 字 |
| 待解问题（L2） | `rules/<剧本>/questions.md` | 读完之后它仍然不确定的事 | 400 字 |
| 印象（L2） | `people.md` | 对**其他玩家**的印象，以名字为键 | 30 人，每条 80 字 |
| 战绩 | `record.json` | 场次、胜场、各身份的胜负；引擎在复盘后累加 | — |

操作笔记、规则要点、待解问题是**自由文本**：初始化和复盘提示 bot 把它们写成几段连贯的话，不要分条列项、不要标题加粗，因为它们会原样放进以后每一局的提示词。

L2 的文件**按剧本分开存**（`rules/<剧本>/` 下）：换一个剧本，旧剧本的规则要点和打法还在，不会混在一起；操作笔记、印象、战绩不分剧本。

### 5.1 一个 bot 会怎样“学”

```text
初始化：读契约和规则 → 写操作笔记、规则要点、打法（把握低、支持 0、反例 0）
   ↓
对局：记忆冻结；bot 只在笔记里记事，用 jot 留线索
   ↓
复盘：对照真相 → 打法的支持 / 反例加一，把握上调或下调，或改写；印象改成“风格、可信度、习惯”；战绩 +1
   ↓
下一局：把握为“中”“高”的打法进系统提示词，带标签的打法在对应时刻被想起
```

### 5.2 打法（playbook）

打法是一个 markdown 文件，一条一行：

```markdown
## 假设
- [把握:中|支持:3|反例:1|来源:复盘 2026-11-20|#对跳|#投票] 两个人都说自己是同一个身份时，先看谁的结论和之后的行动对得上。
- [把握:低|支持:0|反例:0|来源:初始化|#发言] 先听完前面几个人怎么说，再决定要不要表态。
```

方括号里用 `|` 隔开：

- `把握`：`低`、`中` 或 `高`。bot 自己对这条的信心；**只有“中”“高”的条目会进系统提示词**，“低”的只在情境相符时作为“还没验证过的想法”被提起。
- `支持` / `反例`：到目前为止支持它、推翻它的局数；复盘时 bot 自己更新。
- `来源`：这条从哪来（`初始化`、`复盘 <日期>`、`迁移自 v0.13 的经验`……，≤ 40 字）。
- `#标签`：情境标签，可以写多个，**只能用剧本声明过的**（[§4.2](#42-剧本和学习材料l2-官方部分)）。**带标签的条目才会在对应的时刻被想起**；不带标签的，只有在把握为“中”“高”时才通过系统提示词起作用。

`]` 之后是正文，单行、≤ 80 字。解析很宽松：全角括号和冒号都认，不认的行被忽略，没写方括号的条目按“把握：低”处理。

### 5.3 印象（people）

```markdown
- Bob：爱抢第一个发言，但被追问细节就含糊，说过的话很少改口。
- Eve：投票总跟着多数，话少，没有出过格。
```

每行 `- 名字：印象`（名字里不能有冒号，按第一个冒号分）。**只写风格、可信度、习惯，不写“他是什么身份”**：身份每一局都会重新分配。可信度的依据只能是“他说的话后来有没有被事实证实或推翻”“他的行动和他说的话对不对得上”，**不是**话说得有没有条理。开局时只挂载**本局在座的人**的印象（不在座的保留在文件里）。

## 6. 提示词里怎么挂载

这一节解释“我写的东西到了模型眼前是什么样子”。编排器（`app/agents/composer.py`）只准备文字，不替 bot 说话。

**系统提示词在一局里一个字都不变**（所以供应商的前缀缓存能一直命中），顺序是：

| 顺序 | 内容 | 来自 | 预算 |
|---|---|---|---|
| ① | “你是 Alice（本局编号 N3）。”+ 身份、说话方式 | L0 | **不限，不截断** |
| ② | 分析方式，以及附加分区 | L0 | **不限，不截断** |
| ③ | 【我对这个游戏的理解】：规则要点 + “中”“高”的打法，再加一句战绩 | L2 | 规则要点和打法合计约 1600 字 |
| ④ | 【我对在座各位的印象】 | L2 | 1000 字 |
| ⑤ | 【这局游戏的官方规则】 | 剧本里给玩家看的规则 | 不截断 |
| ⑥ | 【平台怎么运作】：契约“必读”段，然后是自己的操作笔记 | L1 | 契约 1200 字、笔记 800 字 |
| ⑦ | 【再提醒一次】：一句身份 + 一句说话方式 | L0 | 各约 48 字 |

- **L0 永远完整**，并且在最前和最后各出现一次，免得被后面的大段规则淹没。
- **自己的记忆渲染成第一人称的段落**（“我很有把握的：……；我觉得多半成立、但还要继续验证的：……”），不是清单：模型会模仿它读到的东西的形状，提示词里放一份清单，就是教它分点说话。契约和规则是官方陈述，保持原样。
- 超出预算时先舍弃的是：把握为“中”且支持最少的打法，然后是印象（排在文件后面的先走）；规则要点、契约、官方规则不动。
- 本局**不加载记忆**（名册 ▾ 里的“本局加载记忆”）时，只挂 L0、官方规则和契约：没有规则要点、打法、印象、战绩和操作笔记。

**事件提示**只出现在**唤醒消息**里，不进系统提示词（所以不破坏缓存）：

- **轮到发言**：说话方式的第一句和篇幅区间；按情境标签检索出的 1–2 条自己的打法（把握低的说成“你还有一个想法，还没验证过”，并且都带上一句“这只是你的假设，和眼前的事实对不上就不用”）；最后一句“先想清楚此刻最关键的一两件事，再一次说完整”。
- **全体一起做的选择（投票）**：“作答之前先问自己：你认定的最硬的事实是什么？”，外加按情境标签检索出的打法。
- **只发给部分玩家的行动请求（比如夜间行动）**：按情境标签，再加上你自己的身份标签检索打法。
- **要用文字回答的问题**：只有按情境标签检索出的打法。
- 后两种在没有相符的打法时不加提示。**不带标签的打法永远不会被检索到**——它们只能靠把握为“中”“高”进系统提示词。

**发言的闸门**只退回、从不改写：

- 超过单条字数上限 → `TOO_LONG`：这一条没有发出，**发言权也没有消耗**，回执写着实际字数和上限；每一次超长都会被退回，引擎从不替任何人（包括真人）截断发言。
- 读起来像报告 → `FORMAT`：连续两行以上以编号或项目符号开头、有标题或加粗、以自己的编号或名字加冒号开头。同一次发言机会里**只退回一次**，bot 用自己的话重写；第二次照原样发出，免得卡住。
- 退回时 bot 在同一次醒来里就能看到回执、改好再发。没有“替它说”的路径：`app/agents/mind.py` 里唯一会碰世界的，是模型自己的工具调用。

## 7. 初始化

初始化是 bot 在**对局之外**做功课：读平台契约和官方规则（以及你放的学习材料），用**自己的话**写下“我对平台怎么运作的理解”“我对这个游戏规则的理解”“我打算怎么玩”“我还不确定什么”。提示词（`prompts/learning/init.md`）明确要求这些都写成假设，不给任何打法。

### 7.1 流程

1. 入口：参与者栏的“⚙ 全局初始化”（默认只处理未初始化、需重新初始化和失败的玩家，另有勾选项“全部重新初始化”），或玩家详情里的“初始化”。只在对局**未开始或已结束**时可用；弹窗列出将要初始化的玩家，可以确认或取消。
2. 每个 bot **并行**，用**自己绑定的模型**（没有绑定的会被拒绝并告诉你）。每个 bot 最多 **120 秒**（真实时间），到点强制结束；进行中可以取消，bot 回到原来的样子。
3. bot 有三个工具：`read_source`（读契约、官方规则、学习材料、自己的底层设定、自己现在的记忆）、`write_memory`（整份写一个记忆文件，写第二次就是覆盖）、`finish`。
4. 要写的文件：**操作笔记、规则要点、打法这三个必须写**，待解问题可选；印象不在初始化里写（它还没和谁玩过）。打法写成 `把握:低|支持:0|反例:0|来源:初始化`。
5. **全有或全无**：三个必需文件齐全、字数和格式都过了检查，才一起原子提交，bot 变成 ✔；任何别的结局——超时、模型调不通、缺文件、超字数——这个 bot 变成 ✖，卡片上写原因，**它原来的记忆一个字都没动**，可以重试。
6. 已经有记忆的 bot 再初始化是**修订**：bot 会先读出现有的记忆，保留还站得住的，改掉它现在觉得不对的；打法条目里已有的把握、支持、反例和来源是以前的对局留下的，原样保留。想**从零开始**，先清除它学到的记忆（详情里的“清除”，或名册 ▾ 里的“清除全部学到的记忆”，不能撤销，建议先导出总存档），再初始化。
7. 费用：初始化**不属于任何一局**，不计入对局预算，单独记在“学习用量”（`bots/usage.json`）；每次运行的过程记在 `logs/learning/<任务>.jsonl`（不含提示词和密钥）。演示模式（`ARENA_DEMO=1`）下由演示机器人用固定回答完成，不调用模型。

### 7.2 状态与开局检查

初始化记录写在 `bot.json` 的 `init` 里：状态、时间、模型、耗时、错误，以及**四个哈希**——初始化时的底层设定、官方契约、剧本和学习材料各自的指纹。界面上的符号：

| 符号 | 状态 | 意思 |
|---|---|---|
| ○ | 未初始化 | 从没初始化过（新建的、从默认库来的、迁移来的、清除过记忆的） |
| ⏳ | 初始化中 | 正在跑 |
| ✔ | 已初始化 | 初始化成功，而且四个哈希都和现在一致 |
| ⚠ | 需要重新初始化 | 初始化之后，底层设定、契约、剧本或学习材料变了（哈希对不上）；会写明是哪一个变了 |
| ✖ | 失败 | 上次初始化没成功，原因写在卡片上 |

**开局检查**：点“开始”时，服务端检查下面这些，**任何一项不满足就不开局**，并按玩家分组列出问题（带“去初始化”“去导入”的按钮）：

| 检查 | 怎么办 |
|---|---|
| 12 个玩家的底层设定都完整（三个必需分区非空、没超限） | 在编辑器里补全，或导入 `.core.md` / 从默认库导入 |
| 12 个玩家都是 ✔（⚠、✖、○、⏳ 都不行） | 初始化（或重新初始化） |
| 每个 bot 的必需记忆文件（操作笔记、规则要点、打法）都在 | 重新初始化 |
| 官方契约和剧本都存在、能解析 | 设置 ③、④ 里导入或恢复默认 |
| 模型绑定齐全 | 在“模型绑定”里给缺的玩家选模型 |

服务端返回 409 和 `NOT_READY`，附带结构化的问题列表；通过检查之后，引擎才**发牌**。

### 7.3 冻结、改名与清除

- 初始化成功后，bot 的**名字和头像冻结**（详情里显示 🔒）：记忆是挂在名字上的，改名就等于换了一个人。点“修改”会弹窗：“修改名字或头像会清空这个玩家的初始化结果和全部记忆（操作笔记、规则要点、打法、待解问题、印象、战绩），底层设定保留。修改后需要重新初始化才能开局。”确认后直接清空（不留副本，待确认的提案也一并丢弃），换一个新的内部 id，状态回到 ○。
- **还没有初始化产出的 bot**（没有成功初始化过，操作笔记、规则要点、打法、待解问题也都是空的）改名、换头像**不弹窗**，原地生效。
- 别的 bot 对旧名字的印象会保留在它们自己的 `people.md` 里；那个名字不在座，就不挂载。
- 名字规则：全表唯一（忽略大小写），1–20 个字，不含控制字符、引号、反斜杠、尖括号和冒号（冒号会截断印象的写法）。

## 8. 复盘

对局结束、真相公开之后，每个 bot 可以回头把自己当时的判断逐个对照真相，修订自己的记忆。

### 8.1 流程

1. **终局弹窗**：“这局结束了，是否让 bot 复盘？”列出 12 个 bot，默认全选；被真人接管过的座位标注“有人类代打”，并带开关“学习接管者的风格”（默认开）。选“暂不”之后，参与者栏的“复盘全部”和“复盘此玩家”仍然可以补做。**每局每个 bot 只复盘一次。**
2. 各 bot **并行**，每个最多 **60 秒**（真实时间）。到点强制结束，**已经写进去的保留**，没写的就没有了——所以 bot 会先写最重要的。
3. bot 看到：自己这局能看到的全部记录（`read_record` 可以翻页、按关键词查）、**全部身份与胜负**（终局后公开）、自己在局中的笔记和 `jot` 线索、自己现在的长期记忆。工具：`read_record`、`read_source`、`write_memory`（可写操作笔记、规则要点、打法、待解问题、印象）、`propose_core`、`finish`。
4. 提示词（`prompts/learning/review.md`）要求的是：把你当时的判断一个一个对照真相，看哪些对了、哪些错了，各自靠的是**规则明确给出的事实、别人说的话、感觉，还是猜的**，然后据此修订记忆：支持某条打法，支持数加一，把握可以上调；推翻了，反例数加一，把握下调或改写；有新想法，写成新的一条，把握先写低、来源写“复盘”。印象只写风格、可信度、习惯，**不写身份**。
5. 写入**立即生效、不回滚**。复盘结束后每个玩家显示改动摘要（新旧对比）和待确认的提案数。需要纠正，就在详情里直接编辑或清除。
6. 这局算进 bot 的**战绩**（模型调不通的复盘不计，可以再点一次）。复盘的费用计入**这一局**的用量和预算。
7. 删除这一局，**不会撤销**复盘已经教给 bot 的东西（删除弹窗里会这么说）。

不能复盘的：没结束的对局、v0.13 存下来的对局（没有 bot 快照）。

### 8.2 L0 只能经提案由你采纳

bot 觉得自己的底层设定某个分区该调整，只能用 `propose_core` **提出建议**（分区、改后的完整文字、理由）。建议**不会自动生效**，出现在玩家详情的“待确认”里，新旧对比一目了然：

- **采纳**：写进对应的 L0 文件（附加分区不存在就新建，已经有 3 份则拒绝），之后底层设定的哈希变了，已初始化的 bot 变成 ⚠，要重新初始化（记忆保留）；
- **拒绝**：删除。

一个 bot 最多同时有 30 条待确认的提案。

### 8.3 向接管者学习风格

这一局里如果有真人接管过某个座位：

- **那个座位的 bot** 复盘时会被告知哪几段是别人代它出场的（记录序号和那个人做了什么），并被邀请把它当作额外的观察材料：哪些做法后来被证明对了，哪些不对，它自己当时会怎么判断。有用的做法可以直接写进打法（把握先写低）。
- 打开“学习接管者的风格”时，它还可以学**那个人说话的方式**：语气、长短、用词、习惯的开头和收尾。但**说话方式只能以 L0 提案的形式提出**，由你确认才生效；提示词要求学方式、不学脏字：辱骂、人身攻击和粗口一律不保留。
- **其他 bot 不会被告诉谁是真人**，它们按真相对照学习：真人说对了，它们的判断就作为“被证明对的”进入学习。

## 9. 默认库与 v0.13 迁移

### 9.1 默认库

仓库的 `bots/` 里有 12 个默认 bot：Alice、Bob、Carol、David、Eve、Frank、Grace、Henry、Ivy、Jack、Kate、Leo（头像固定）。它们的底层设定互不相同（篇幅、语气、分析方式都不同，前提都是“想赢”），不含任何游戏词汇和打法。

- **首次运行**（数据目录里没有 `bots/`，也没有 v0.13 的 `roster/`）时，复制成默认阵容。复制出来的 bot 是○，要先初始化才能开局——除非库里的 bot 自带了已初始化的记忆（发版前用 `tools/init_default_bots.py` 可以做一次；写法和守卫见 [bots/README.md](../bots/README.md)、[real-model-runs.md](real-model-runs.md)），那样它们一启动就是 ✔，直到你改了契约或剧本。
- **从默认库导入**（玩家详情里的按钮）：用库里的某个 bot **整体覆盖**当前玩家（名字、头像、底层设定，以及库里带的记忆）。名字与桌上别的玩家重名时会被拒绝。
- 库里的文件只是模板：复制之后每个 bot 有自己的内部 id，之后怎么改都不影响库。

### 9.2 从 v0.13 升级

升级是**自动**的，不调用任何模型：第一次启动 v0.14、数据目录里有 `roster/` 时，名册被转换成 12 个 bot（导入 v0.13 的总存档时同样）。`roster/` 本身**原样留着**，不再被读写。

| v0.13 | v0.14 |
|---|---|
| 12 个座位的名册：名字、头像 | 12 个 bot，名字、头像沿用（名字里的冒号换成空格；本局加载记忆的开关和主持人头像也沿用） |
| 性格里的 `【定位】` | 身份 |
| `【说话风格】`、`【口头禅】` | 说话方式（口头禅加前缀“口头禅：”） |
| `【思考方式】`、`【决策偏好】`、`【压力下】` | 分析方式（后两项加前缀“决策偏好：”“压力下：”） |
| **没有标题的手写性格**（自己在文本框里敲的，不是用“完善”按钮按模板生成的） | **不丢字**：前 300 字（在句末切，不切在句子中间）进身份，超出的部分按原文顺序依次进最多 3 个附加分区“原有性格（续）”“原有性格（续二）”“原有性格（续三）”（每份 ≤ 300 字，同样在句末切）。**说话方式、分析方式留空**——用「✨ 用主持人模型完善」让主持人模型根据现有设定补全，或者自己手写，否则这个 bot 开不了局。只有一句话就超过一个分区的上限时才在句子中间切开：这一份以“…”结尾，下一份从切开的地方接着写。空白和换行保持原样 |
| 带标题的性格里，某一段超过了新的字数上限 | 多出的部分先溢出到还空着的附加分区（“原有·身份（续）”“原有·说话方式（续）”“原有·分析方式（续）”），装不下的才以“…”截断 |
| 四个地方（身份 300 字 + 3 × 300 字）一共装不下的部分 | 以“…”截断；完整的原文仍在旧的 `roster/` 里，没有被改动 |
| **性格为空** | L0 缺失；**但名字恰好是 Alice…Leo 之一的，用默认库里同名 bot 的底层设定补上**（名字、头像、记忆仍是迁移来的）。其他名字的 bot 照旧缺失，要自己写 |
| 印象（以座位号为键） | 以名字为键（按当时名册的名字） |
| 经验 | 把握为“低”的打法条目，来源“迁移自 v0.13 的经验” |
| 战绩 | 保留 |
| v0.13.0 写的自由文本记忆 | **不迁移**（里面没有说谁、有多确定），留在旧文件里 |
| 按座位保存的默认模型绑定 | 移到现在坐在那个座位上的 bot |
| 初始化状态 | 全部○：升级后点一次“⚙ 全局初始化” |

- 迁移后可能有几个 bot 的底层设定不完整：没写过性格、名字又不是默认名字的，整份都缺；手写过自由文本性格的，有身份和“原有性格（续）”，缺说话方式和分析方式。它们不能开局，开局检查会指出来；写一个、导入一个、从默认库导入，或者对手写性格的 bot 点「✨ 用主持人模型完善」（它读现有设定补出说话方式和分析方式，先给你看草稿，你确认了才保存）。**不会自动用默认库补**：默认库的说话方式是为那个默认人设写的，拼在你自己写的性格后面会互相打架。
- **v0.13 的对局**（存档格式 v5）照常能载入、重放、继续：继续时全部座位用 `LegacyBrain`——原样使用存档里的性格和记忆，和 v0.13.1 的行为逐字节一致——**不做开局检查，也不能复盘**。新开的对局存档为 v6，继续时用存档里的 bot 快照重建提示词，不读当前文件。

## 10. `.arenabot`：交换一个 bot

一个 `.arenabot` 就是一个 bot 的全部状态：名字、头像、底层设定、全部记忆、战绩、初始化记录和待确认的提案。它是一个 zip（有清单和每个文件的 SHA-256），文件名 `<名字>-YYYYmmdd-HHMMSS.arenabot`。

- **导出**：玩家详情里的“导出”。**导入**：玩家详情里的“导入”，选一个文件。
- 导入是**覆盖**：弹窗确认“将用文件里的 bot 覆盖 Alice：名字、头像、底层设定、记忆都会被替换”。目标玩家的内部 id 不变（所以座位、模型绑定都不变）；文件里的 id 被忽略。名字和桌上别的玩家重名就拒绝；文件里的字数超限或格式不对也拒绝，并列出每一处。覆盖是一次完成的，失败时原来的 bot 原样不动。
- 导入之后，初始化状态由哈希重新判断：同一份契约、剧本、底层设定做出来的初始化是 ✔，对不上的是 ⚠。
- 一个文件最大 20 MiB。里面**不含** API Key、契约、剧本、对局和日志（总存档才有，见 [archive.md](archive.md)）。
- 文件是明文的 zip，里面有 bot 的记忆：**分享之前自己看一眼**。导入也别导入你不信任的文件——校验能发现损坏，但没有签名。

## 11. 与基准的关系

v0.14 的两个目标——各玩家的发言风格不同、依据硬事实而不是“讲得有条理”做判断——是用 `bench/` 量化的：同一套度量先在 v0.13.1 的真实对局上测出基线，再看 v0.14 的变化。

- **`LegacyBrain` 是基线。** 它就是 v0.13.1 的玩家（和 v0.13.1 逐字节一致，也是继续 v5 对局用的那个）；被测的是 `BotBrain`（v0.14 的 bot）。基准里的发言同样必须由 bot 自己产生：局面脚本用真实引擎搭好世界，跑真实的 agent 循环，直到 bot 自己行动。
- 你不需要跑基准也能用 bot。想比较自己改过的 bot 和基线，用假模型能把流水线跑通（它的数字**什么都不说明**），要有意义的数字得用真实模型和裁判：

  ```bash
  python -m bench run --include-examples --bots legacy,bot:Alice --samples 2 --fake mixed
  ```

  真实模型必须显式 `--real` 并给 `--max-calls`；完整的用法、局面脚本的写法、结果文件的格式和验收门槛在 [bench/README.md](../bench/README.md)。
- 默认 bot 库的初始化和真实模型冒烟另有脚本：见 [real-model-runs.md](real-model-runs.md)。

## 12. 常见问题

| 现象 | 原因 / 做法 |
|---|---|
| 点“开始”弹出一个问题列表 | 开局检查（[§7.2](#72-状态与开局检查)）：按玩家逐项处理，点“去初始化”“去导入”直达 |
| 一个 bot 刚改完底层设定就变 ⚠ | 正常：初始化是用旧的底层设定做的。重新初始化即可，记忆保留，它会修订而不是重来 |
| 所有 bot 一起变 ⚠ | 你导入或恢复默认了契约、剧本或学习材料；重新初始化一次 |
| 初始化 ✖：“时间到了（120 秒）” | 模型太慢。重试，或给这个 bot 换一个更快的模型；原来的记忆没动 |
| 初始化 ✖：“没有写完必需的文件” / “写入没有通过检查” | 模型没写全或超了字数；重试。反复出现就看它的底层设定是不是把任务搞复杂了 |
| 提示“没有绑定模型” | 在“模型绑定”里给这个玩家（座位）选模型；绑定是跟着 bot 走的 |
| 一个 bot 总被 `FORMAT` 退回 | 它的说话方式在引导分条：改成散文；真的需要分条就单独写一行 `允许口头列举` |
| 一个 bot 总被 `TOO_LONG` 退回 | 它的 `篇幅：a–b 字` 超过了单条上限；调小。状态板和唤醒消息里写着当前的上限 |
| 想把一个 bot 学到的东西全部丢掉 | 玩家详情“记忆”里的“清除 xxx 的全部记忆…”，或名册 ▾ → 清除全部学到的记忆；底层设定保留，状态回到 ○。不能撤销，先导出 |
| 想换一个剧本玩 | 设置 ④ 导入剧本；所有 bot 变 ⚠，重新初始化（新剧本的规则要点和打法单独存，旧剧本的还在） |
| 手改了数据目录里的 bot 文件 | 最稳妥是服务停止时改、改完再启动。服务在跑时改的，进行中的这一局不受影响（它用开局的快照），下一局才用；界面可能要刷新页面才看得到 |
