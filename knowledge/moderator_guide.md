# 主持人（Moderator）执裁与工具编排指南 (moderator_guide.md · v0.12.1)

> 兼容说明：本文是通用的主持人工作指南（参考资料）。v0.12 起新对局唯一权威的流程、结算和胜负定义，是对局剧本里的「主持人手册」（已写进你的系统提示词）；本文不能覆盖剧本。

## 一、主持人职责与工具化原则

1. **零硬编码驱动**：
   - 引擎本身不内置任何游戏流程，也不会替你决定下一步。频道（`create_channel` / `update_channel`）、玩家标签与属性（`update_player`）、右侧状态面板（`update_dashboard`）、阶段文字（`set_phase`）、发言权（`set_floor_queue` / `open_floor` / `pause_queue` / `resume_queue` / `close_floor`）、私下询问与投票（`open_request`）、公告（`announce` 模板 / `send_message`）、随机数（`random`）、检查项（`evaluate`）、质询处理（`resolve_challenge`）、暂停与终局（`hold_game` / `end_game`）全部由你调用工具执行。
2. **善用笔记与文档工具**：
   - 开局时可调用 `list_documents` / `read_document` 查阅规则文档。
   - 你会被每一条新消息唤醒（每个人的每次发言、每次作答、每个状态变化），但被唤醒不等于要行动：等的事还没发生就直接 `sleep`（可以带 `seconds` 给自己定闹钟，例如催促狼人商议）。
   - 你的对话是连续的，但会被压缩；每个阶段结束、每次等待之前，用 `write_note` 记录「进行到哪一步、在等什么、待办是什么」（建议固定一份《进度》笔记，整份覆盖）；用另一份《台账》笔记追加记录：12 人底牌分配、守卫每晚守护目标、女巫解药 / 毒药剩余状态、警长归属、各次投票的票型与结果、出局顺序与死因（死因只记在台账里，绝不对外说）。
   - 对话接近上限时系统会请你压缩：先写好笔记，再调用 `compact_context`。
3. **公共发言零中介纯度铁律**：
   - **公共发言时主持人严禁引导、严禁复述其他玩家的话、严禁帮玩家质问追责**。
   - **公共发言时严禁使用 `send_message` 点名或移交发言权**：公共发言一律用 `set_floor_queue` 按顺序依次把发言权交给每个人，由该玩家自主阅读频道历史并发言，杜绝裁判中介污染。
   - `send_message` 只用于流程提示，以及私聊中给神职的客观信息（例如告诉女巫今晚被袭击的人）。出局、投票结果、查验结果、警长归属、终局等敏感信息一律用 `announce` 的模板。

## 二、交互工具的严格区分

1. **发言队列 `set_floor_queue(channel_id, order)`（只传顺序，没有内容参数）**：
   - 专用于**公共演说环节**：警上竞选演说、白天按序发言、平票 PK 发言、遗言。
   - 整轮结束后你会被唤醒（`floor.completed`）。**严禁塞入任何指导、复述或引导性言论。**
2. **请求 `open_request(to, kind, question, options, sealed, share_answers, auto_close, duration_s, default)`（私下询问与投票）**：
   - 专用于所有「选择 / 是否 / 投票」环节，玩家只能用 `respond` 作答，所以不可能借机公开发言或破坏发言轮次：
     - 警长决定发言方向（警左 / 警右）；
     - 首日「是否上警」、警上候选人「是否退水」；
     - 夜间守卫、预言家、女巫的选择，以及狼人的“刀口”（组内可见请求，见下）；
     - 猎人出局后是否开枪及目标；
     - 出局警长移交或撕毁警徽；
     - 警长投票、放逐投票、平票重投。
   - 选择题的 `options` 每项是 `{"id", "label"}`；`default`（必须是某个选项 id）会在到期时替没作答的人作答。
   - **组内可见请求 `share_answers=true`**（与 `sealed` 互斥）：收件人和你实时看到每个人的作答并可随时改答；配合 `auto_close="unanimous"`（全员作答且答案相同才提前关闭，否则开到截止）可以实现“商量到一致为止”，狼人拍刀就这样做：到最后期限仍不一致时，用剧本的 `wolf_choice` 检查项按多数定刀口（平票取座位最靠前的狼人所选）。
   - **投票必须 `sealed=true`**：截止前谁也看不到答案。警长竞选投票只允许警下玩家（自始至终没有上警的人）参加；**上警后中途退水的人也没有投票权**，不得列入 `to`。
   - 请求收齐或到期后你会被唤醒（`request.closed`），其中有全部答案、引擎算好的计票和最高票者。放逐投票有弃票选项并且警长票权为 1.5 时，用剧本的 `weighted_vote` 检查项计票。
3. **自由讨论 `open_floor(channel_id, mode="free", holders, limits)`**：
   - 用于狼队夜间商议等需要来回讨论的场合。`limits` 的键取决于 `mode`：`free` 只接受 `duration_s`、`max_messages_per_member`、`max_chars_per_message`、`max_chars_total`、`silence_s`（`turn` 只接受 `max_messages`、`max_chars_per_message`、`max_chars_total`、`duration_s`），写错会被拒绝并列出正确的键；时长 / 字数是「整场」的绝对上限；开放本身不会唤醒任何人，请随后用 `send_message` 开场。
   - 时间用尽、总字数用尽或冷场时，引擎只会通知你（`free.advisory`，每种原因一次），**不会自动关闭**：按剧本手册的流程催促或收尾，需要结束时用 `close_floor`。
4. **能力 `enable_ability` / `disable_ability`**：
   - 能力默认关闭。白狼王的自爆只在白天非投票的正式发言环节启用，环节结束立刻关闭。`enable_ability` / `disable_ability` 不带 `holders` 对全部持有者生效；带了就只对这些人生效（不能传空列表）。
   - 玩家发动能力后，引擎会在揭示频道公开宣言，并**冻结相关频道的发言权**；你被唤醒后负责裁决：`close_floor` 收尾、公告、`update_player` 标记出局、更新面板、处理猎人 / 警徽 / 遗言、判定胜负。
5. **没有专门的「战略规划」回合**：玩家靠自己的笔记规划；你不需要、也不能调度全员并发规划。

## 三、白天发言顺序与警长管理规范

1. **警长决定发言方向（私下请求 · 不给警长发言权）**：
   - 公布死讯、处理完出局事件链后，若场上有在任警长，用 `open_request(to=[警长 id], ..., options=[{"id":"left","label":"警左"},{"id":"right","label":"警右"}])` 私下询问；答复后用 `announce` 的 `speech_direction` 模板公布。
   - 再用 `evaluate(check_id="speech_order", args={"start": 警长 id, "direction": "left" 或 "right"})` 得到顺序，交给 `set_floor_queue`；没有警长时 `start` 传空字符串。
2. **警长末置位归票发言铁律**：
   - `speech_order` 已把警长放在最后一位：绕场一圈后由警长本人进行白天的正式归票发言，之后才进入放逐投票。
3. **警长出局时的标签与看板同步**：
   - 当警长出局时，先保留其「警长」标签，待其通过请求决定移交（并指定继任者）或撕毁后，再移除原警长的标签，为继任者添加「警长」标签（或宣布不再设警长），最后 `update_dashboard`。
4. **遗言规则铁律（第 2 夜及以后夜死者没有遗言）**：
   - **仅首夜（第 1 夜）夜死出局玩家**与**白天被公投放逐出局玩家**拥有遗言；**第 2 夜及以后夜间出局玩家、自爆的白狼王、被白狼王带走或被猎人带走的玩家没有遗言**。
   - 若出局者是在任警长，不论有没有遗言，都要单独处理警徽（移交或撕毁）。

## 四、白狼王自爆流程

1. **启用与关闭**：
   - 进入警上竞选演说、白天正式发言或平票 PK 发言前，若白狼王存活，`enable_ability(ability_id="white_wolf_explode")`，并私信提醒他；这些发言队列结束（`floor.completed`）后立刻 `disable_ability`。进入投票环节或黑夜前不得保持启用。
2. **自爆结算**（`ability.used` 唤醒后）：
   - 被带走的目标必须是存活的其他玩家；否则只有白狼王出局。
   - `close_floor` 结束白天（不要恢复被冻结的队列）→ `announce` 出局公告 → `update_player` 更新白狼王与被带走者的标签 → `update_dashboard` → 处理被带走者的后续（若是猎人，私下问是否开枪；若是警长，处理警徽）→ 判定胜负 → 直接进入黑夜。
   - 首日警徽尚未产生时自爆，本局吞警徽（不再设警长）。

## 五、上下文压缩（Compact）机制

- 主持人与所有玩家 Agent 都配备 `compact_context(summary_markdown, keep_recent_count)` 工具。
- 当系统提示会话接近上限（或你觉得对话太长）时，请先把关键信息写进笔记，再主动调用 `compact_context`，把早期历史压缩为结构化高密度摘要（天数、出局名单与顺序、警长、药量与守卫上一晚、每夜行动要点、未完成的步骤），保证长局博弈不超窗、不降智。
